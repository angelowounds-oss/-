# AETHER Wind Tunnel

브라우저(크롬)에서 도는 실시간 3D 유체 시뮬레이션 + 인터랙티브 풍동 씬.
**정성적 시각화이며 공학 해석 도구가 아닙니다.** (점성·난류 없음, 격자 10~16cm)

## 열기

- `aether/index.html`을 크롬에서 엽니다. 서버 필요 없음(로컬 파일 열기 가능).
- 주소 뒤에 붙이는 옵션

| 옵션 | 뜻 |
|---|---|
| `#q=LOW` / `MED` / `HIGH` / `ULTRA` | 격자 등급 강제 지정(자동 조절 꺼짐). 생략하면 GPU 종류로 자동 선택 |
| `#perf=1` | 프레임 ms, GPU 등급, 연기 해상도, 화면 배율, 자동 조절 기록 표시 |
| `#bench=cylinder` | 차량 대신 지름 0.5 m 원기둥으로 스트라우할 수 벤치마크 |

내장그래픽 PC라면 옵션 없이 열면 됩니다. LOW로 시작해 프레임이 여유 있으면 화질을 단계적으로 올립니다.

## 폴더

```
index.html          진입점
css/style.css
js/engine.js        (빌드 산출물)  엔진 전체. 수정하지 말고 src/를 고칠 것
js/ui.js            (빌드 산출물)
src/engine-a.js     엔진 앞부분      ┐ tools/build.py 가 이어 붙여 js/engine.js 생성
src/live-cfd.js     실시간 CFD 전체  │ (엔진이 하나의 IIFE라 파일을 그냥 나눌 수 없음)
src/engine-b.js     엔진 뒷부분      ┘
src/ui.js
assets/*.js         차량·팬·콘솔·워커 base64 (엔진 상수로 그대로 사용)
original/           원본 단일 HTML (기준본, 수정 금지)
tools/split.py      원본 → 분리 (1회용)
tools/build.py      src → js/  ,  --standalone OUT.html 이면 16MB 단일 파일 생성
docs/               작업 지침서
```

빌드: `python3 aether/tools/build.py` (src를 고치면 반드시 실행).

## 이번 작업에서 바뀐 것

| 항목 | 내용 | 상태 |
|---|---|---|
| 파일 분리 | 단일 16MB → index/css/js/assets. 분리 전후 측정값 동일 | 검증됨 |
| 멀티그리드 | V-cycle 3레벨. 기본 솔버. `LIVE.solver='JACOBI'`로 되돌릴 수 있음 | 검증됨(헤드리스) |
| 항력·양력 | 차량 표면 압력 적분으로 Cd/Cl 표시 | 구현됨, 값은 참고용 |
| 원기둥 벤치마크 | 스트라우할 수 측정 | 구현됨, **문헌값과 불일치** |
| 화질 체계 | LOW/MED/HIGH/ULTRA, GPU 판별, 프레임타임 기반 자동 조절 | 로직 검증됨, **실제 iGPU 프레임은 미측정** |
| 연기 렌더 | 저해상도 오프스크린+합성, 빈 공간 건너뛰기, 그림자 다중 탭, 디더 | 화면 확인됨, 성능 미측정 |

### 1. 멀티그리드 vs 야코비 (LOW 112×36×52, 풍속 5 m/s, dt=0.02, 120스텝, 헤드리스 SwiftShader)

시간은 CPU 에뮬 기준이라 **상대 비교용**입니다.

| 솔버 | 스텝당 시간 | Poisson 잔차 RMS | div 상대 RMS | div 상대 최대 |
|---|---|---|---|---|
| 야코비 16회 | 0.28 s | 3.4e-4 | 0.0051 | 0.475 |
| 야코비 32회 (기존) | 0.47 s | 1.5e-4 | 0.0050 | 0.475 |
| 야코비 64회 | 0.83 s | 7.0e-5 | 0.0050 | 0.475 |
| **멀티그리드 1사이클 (기본)** | **0.21 s** | **2.7e-5** | 0.0050 | 0.475 |
| 멀티그리드 2사이클 | 0.30 s | 7.3e-6 | 0.0051 | 0.475 |

- 기존 32회 대비 시간 약 절반, 잔차 약 5배 낮음.
- **투영 후 발산(div)은 그대로**입니다. 원인은 솔버 수렴이 아니라 격자 구조(속도·압력 같은 위치 + 7점 라플라시안과 중심차분의 불일치)라서, MAC 격자(지침 7번)로 가야 줄어듭니다. 멀티그리드는 이 한계를 못 고칩니다.
- 보정계수 1.0(표준)은 시간 적분에서 발산했습니다(재이산화 조대격자가 보정을 과대 추정). 0.6~0.8에서 120스텝 안정, 0.75 채택. 4레벨도 발산해서 3레벨로 제한.
- MED/HIGH 격자에서도 40스텝 안정 확인. 발산 감시 장치: 힘 값이 NaN이거나 과대하면 자동으로 야코비로 되돌리고 초기화.

### 2. 항력·양력 계수

- 차량 복셀 표면에 닿는 유체 셀의 압력 × 면적을 GPU에서 합산 (`P = ρ·p/dt`, 8×8 블록 리듀스, PBO 비동기 읽기).
- 자체 점검: 균일 압력을 넣으면 x·z 힘은 0(닫힌 물체), y 힘은 차 바닥이 바닥판에 붙어 있어서 남음(정상).
- LOW 격자, 약 2.4 s 시점 Cd ≈ 1.0, MED/HIGH도 1.0~1.3 범위. 실차 GT3(약 0.4~0.5)보다 큼.
  **이유: 마찰항력 없음(비점성), 복셀 계단 형상, 셀 크기(10~16cm)가 지상고(약 7cm)보다 커서 차 밑이 막힘.**
  절대값이 아니라 형상·풍속을 바꿨을 때의 상대 변화만 봐야 합니다. 화면에도 그렇게 표기했습니다.
- Cl은 격자 등급에 따라 부호까지 바뀝니다(시작 후 0.6 s 시점 기준 LOW +0.6, MED −0.2, HIGH −1.0). **신뢰하지 마세요.**

### 3. 원기둥 벤치마크 (지름 0.5 m, 풍속 5 m/s, 문헌 St ≈ 0.2)

| 격자 | 지름당 셀 수 | 측정 주파수 | St | 문헌 대비 |
|---|---|---|---|---|
| LOW | 3.3 | 0.87 Hz | 0.087 | −57% |
| MED | 4.2 | 1.13 Hz | 0.113 | −43% |
| HIGH | 5.1 | 0.27 Hz | 0.027 | −87% (느린 후류 요동, 와류 방출 아님) |
| LOW, 지름 1.0 m | 6.5 | 0.65 Hz | 0.130 | −35% |

**검증 실패입니다.** 지름이 3~6셀이면 수치 확산이 와류 방출을 지배하고, 결과가 격자에 따라 단조롭지도 않습니다(HIGH가 가장 낮음). 이 솔버의 후류는 모양(갈라짐·역류)만 정성적으로 의미가 있고, 주파수·항력·박리 위치는 신뢰할 수 없다는 지침서의 한계 항목을 실측으로 확인한 것입니다. 신뢰할 수 있는 값을 얻으려면 MAC 격자 + 난류 모델 + 지름당 20셀 이상이 필요합니다.

### 4. 화질·성능 (내장그래픽 대응)

**실제 내장그래픽에서는 측정하지 못했습니다.** 이 환경은 GPU가 없어 CPU 에뮬로만 돌렸습니다. 확인된 것: 오류 없이 부팅, 등급 전환(LOW→MED→HIGH→LOW), 조절 로직의 올림/내림 순서, 화면 결과. 프레임 수는 직접 확인이 필요합니다.

- GPU 등급별 시작값(추정치): 내장그래픽 LOW·연기해상도 62%·캔버스 픽셀 배율 상한 1.25, Apple 실리콘 MED, 외장 HIGH, 모바일 LOW.
- 프레임 32 fps 미만이면 한 단계 내림(연기 해상도 → 화면 배율 → 서브스텝 → 조명 탭 → 격자 등급). 프레임 간격 18 ms 미만이 30프레임 이어지면 한 단계 올림, 격자 등급 올림은 240프레임(약 4초) 여유가 있을 때만. 동작 확인은 프레임 시각을 합성해 넣는 시뮬레이션으로 했습니다.
- `#perf=1`로 켜서 화면에 나오는 `프레임 ms`, `조정:` 기록을 보내주시면 시작값을 실측 기준으로 고칠 수 있습니다.

## 알려진 한계 (지침서 3장 + 이번 확인)

1. 점성·난류 없음. 항력계수·박리·주파수 신뢰 불가 (위 벤치마크로 확인).
2. 셀 10~16cm. 사이드미러·윙 끝단·바퀴 디테일·차 밑 틈이 복셀에 뭉개짐.
3. 투영 후 발산 최대 약 47%가 고체 경계에 남음(격자 구조 한계, 솔버 문제 아님).
4. 바퀴 회전 무시, 바닥 전체가 벨트.
5. 연기가 장비 일부를 뚫고 보일 수 있음.
6. **차량 에셋 재배포 권리 미확립.** 상업 게시 전 교체 필수.
7. 벤치마크 모드는 화면에 차량이 그대로 보이지만 계산에는 포함되지 않음.

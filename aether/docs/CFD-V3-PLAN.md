# CFD V3 계획: 국소 세분화 LBM + GPU 컴퓨트

목표는 두 가지입니다. 하나는 **속도**로, 같은 기기에서 차 주변 셀을 지금의 24 cm(LOW)에서 3~6 cm로 줄이는 것입니다. 다른 하나는 **정확도**로, 격자를 줄일수록 공개 벤치마크 값에 단조롭게 다가가는 솔버를 만드는 것입니다. 외부 CFD 코드는 쓰지 않습니다. 공개 문헌의 이론과 벤치마크 수치만 사용하고, 구현은 모두 이 저장소에서 합니다.

이 문서의 계산값은 아래 식과 `node` 계산으로 재현할 수 있습니다. 기기 대역폭과 실효 효율은 **미확인 가정**이며, 사용자 기기에서 재야 확정됩니다.

## 1. 지금 솔버가 느리고 부정확한 이유 (측정과 이론)

### 1.1 비용 법칙
명시적 시간 적분을 쓰는 균일 격자에서 물리 시간 1초에 드는 일은 다음과 같습니다.
- 셀 수 = V / h³
- 스텝 수 = U / (c·h)
  - c는 CFL 계수입니다. LBM에서는 격자 속도 u_lat에 해당합니다.

따라서 **일 ∝ V·U / (c·h⁴)**입니다. h를 절반으로 줄이면 비용이 16배가 됩니다.

### 1.2 낭비
- 계산 영역은 플레넘 전체(33.5 × 8 × 13 m = 3,484 m³)입니다.
- 차와 근후류에 높은 해상도가 필요한 상자는 약 7 × 2.4 × 3 m = 50 m³로, 전체의 **1.4 %**입니다.
- 나머지 98.6 %에도 같은 h를 쓰고 있습니다.

### 1.3 투영법의 구조적 비용
- MAC 투영법은 매 스텝마다 전역 압력 푸아송 방정식 ∇²p = ∇·u*/Δt를 풉니다.
- 현재 구현은 RBGS 다중격자로, V 사이클 2회 × 4단계 × (전처리 2 + 후처리 2) 패스입니다.
- 정보가 영역 전체로 퍼져야 하는 타원형 문제라, GPU에서는 패스 수와 동기화 비용이 지배합니다.
- `PERF.md` §4(SwiftShader 상대 비교)에서 압력 풀이가 스텝 비용의 대부분입니다.

### 1.4 정확도 문제 (측정)
- Ahmed 25°: Cd 0.63~0.80으로, 문헌값 0.285의 약 2.2배입니다.
- BMW: 격자를 줄이면 Cd가 0.60 → 0.78 → 1.10으로 **문헌과 반대 방향으로 갑니다**(L36).
- 원인 후보는 세 가지입니다.
  - ① 부분체적 경계(vf)의 일관성 오차(L5)
  - ② 벽 모델 없이 18~34 cm 셀을 씀
  - ③ 비보존형 이류(L6)
- 솔버 V2 시제품 비교(S0)에서는 같은 투영법 계열이 원기둥에서도 문헌으로 수렴하지 않았습니다(Δp −8.7 %). 반면 LBM + Bouzidi는 수렴했습니다(+0.22 %, 수렴 차수 1.3~2.2).

## 2. 이론적 근거: 왜 이 조합인가

### 2.1 격자 볼츠만(LBM)
- 채프먼–엔스코그 전개로, 약압축성 나비에–스토크스 방정식을 다음 조건에서 복원합니다.
  - 점성: ν = c_s²(τ − ½)Δt, c_s² = 1/3
  - 오차: O(h²) + O(Ma²)
- 압력은 상태방정식 p = c_s²ρ에서 나옵니다. **전역 풀이가 없고**, 셀마다 이웃 19개 값만 읽습니다.
- 대가는 마하수 제약입니다. u_lat ≲ 0.1이어야 하므로 Δt = u_lat·h/U이고, 투영법보다 스텝 수가 5~10배 많습니다.
  - S0에서 u_lat을 0.06에서 0.03으로 줄여도 Cd 차이는 0.01 %였습니다. 0.1 부근까지는 검증하고 씁니다.

### 2.2 메모리 대역폭 한계
- LBM은 계산량보다 메모리 이동으로 제한됩니다.
- D3Q19에서 한 셀 갱신에 읽기 19개와 쓰기 19개가 듭니다.
  - FP32: 152 B
  - FP16 저장(f − w_i를 저장하는 이동 표현): 76 B
- 이론 상한 = 대역폭 ÷ 76 B입니다.
  - 50 GB/s 기기: 0.66 GLUPS
  - 500 GB/s 기기: 6.6 GLUPS
  - 실효 효율 30~60 %는 **미확인 가정**입니다.

### 2.3 국소 세분화 (2:1 중첩 블록 + 시간 세분화)
- 단계 l의 셀 크기는 h·2^l입니다. 굵은 단계는 2^l 스텝마다 한 번만 갱신하므로, 일은 가장 촘촘한 상자가 지배합니다.
  - 일 ≈ V_f·U / (u_lat·h_f⁴)
- 계산 결과(상자: 50 / 240 / 960 m³ / 나머지, U = 5 m/s, u_lat = 0.1):

| 차 주변 h | 중첩 셀 수 | 실시간 1:1에 필요한 처리량 | 같은 h 균일 격자 | 일 감소 |
|---|---|---|---|---|
| 24 cm (현재 LOW) | 0.01 M | 0.001 GLUPS | 0.25 M셀 | 53배 |
| 6 cm | 0.42 M | 0.25 GLUPS | 16 M셀 | 53배 |
| 4 cm | 1.41 M | 1.3 GLUPS | 54 M셀 | 53배 |
| 3 cm | 3.34 M | 4.1 GLUPS | 129 M셀 | 53배 |

- 여기에 §2.2의 상한을 대입하면 다음과 같이 추정됩니다. **둘 다 미확인 가정 기반입니다.** P0에서 FP16 저장이 정확도 기준을 통과하지 못해 기본은 FP32(152 B)입니다.
  - 휴대폰(약 50 GB/s × 50 %): 실시간 1:1로 **h ≈ 6.7 cm** (FP16이었다면 5.6 cm)
  - 데스크톱 GPU(약 500 GB/s × 50 %): **h ≈ 3.8 cm** (FP16이었다면 3.2 cm)
- 실시간 1:1을 포기하고 모의 시간을 벽시계보다 느리게 흘리면(예: 0.25배) h를 4^(1/4) = 1.41배 더 줄일 수 있습니다. 지금도 HUD에 모의 시간이 표시됩니다.
- 접합면 처리:
  - 비평형 부분의 배율 변환: 굵은 쪽 f^neq = (2τ_c/τ_f)·f^neq 미세 쪽 (Dupuis–Chopard 2003, 절점형)
  - 질량을 보존하는 체적형(Rohde 외 2006)
  - 두 방식을 모두 구현하고 아래 접합면 시험으로 고릅니다.

### 2.4 고 레이놀즈수: 충돌 연산자와 LES
- 차의 Re는 U·L/ν = 5 × 4.7 / 1.5e-5 ≈ **1.6 × 10⁶**입니다.
- τ가 ½에 가까워지면 TRT는 발산합니다(S1에서 셀 Re 30에서 발산 확인).
- S1에서 검증한 **정규화 + Smagorinsky**는 셀 Re 10,000까지 안정이었습니다.
- 누적량(cumulant, Geier 2015)은 해상도가 부족할 때 더 낫다고 보고되어 있습니다. 필요성이 측정으로 확인될 때만 도입합니다.

### 2.5 벽: 보간 bounce-back과 벽 모델
- Bouzidi(2001)는 표면까지의 실제 거리 q를 쓰는 2차 정확도 벽입니다. S0에서 계단 경계의 +43 % 오차를 없앴습니다.
- 첫 셀 중심의 y+는 (h/2)·u_τ/ν이고, u_τ = U√(Cf/2)이며 Cf는 0.002~0.004로 가정합니다.

| h | y+ |
|---|---|
| 24 cm | 1,265~1,789 |
| 6 cm | 316~447 |
| 3 cm | 158~224 |

- 3~6 cm에서 첫 셀은 **로그 영역**(y+ ≈ 30~500)에 들어갑니다. 그래서 벽 법칙(Reichardt 또는 Spalding 식, κ = 0.41, B = 5.2)으로 벽 전단을 주는 **벽 모델 LES**가 이론적으로 성립합니다. LBM 적용은 Malaspinas–Sagaut(2014) 방식을 따릅니다.
- 24 cm에서는 형상 자체가 해상되지 않아, 벽 모델로도 구할 수 없습니다. 이것이 지금 Cd 오차를 설명하는 유력한 원인입니다(추정).

### 2.6 힘
- 운동량 교환법(갈릴레이 불변형, Wen 외 2014)을 씁니다. 표면 링크마다 계산하므로 압력과 마찰 지도를 함께 얻습니다.

### 2.7 GPU 구현
- **WebGPU 컴퓨트(주 경로)**: 저장 버퍼에서 제자리 스트리밍(AA 패턴 또는 esoteric twist)을 하므로 버퍼가 1개이고 메모리가 절반입니다.
- **WebGL2(대체 경로)**: 핑퐁 텍스처(19값 → RGBA 5장, MRT)를 쓰고 3D 슬라이스마다 그려야 해서 효율이 낮습니다.
- WebGPU는 현재 크롬과 안드로이드에서 정식 지원됩니다. iOS는 Safari 26부터 지원한다고 알고 있지만 **실기 미확인**입니다.

|---|---|---|
| FP16S (w_q를 빼고 2^15배, IEEE half) | +0.44 % | **+0.86 %**, 마지막 10 D/U 변동 1.2 %로 수렴 기준 미달 |
| FP16C (가수 11비트) | +0.14 % | **+0.57 %** |

- 반올림 함수는 정확한 기준과 55만 8천 건(FP16S), 40만 4천 건(FP16C)을 대조해 불일치가 0입니다(`tools/solver2/tests/f16-round.mjs`). 계산은 Float64이고 메모리에 쓸 때만 반올림합니다.
- 이론과 일치합니다. 저장 오차는 (f − w)의 가수 정밀도로 정해지고, 그 크기는 u_lat에 비례해 해상도와 무관합니다. 반면 점성 응력을 실어 나르는 f^neq는 h에 비례해 줄어듭니다. 따라서 상대 오차가 해상도에 비례해 커집니다. 실제로 D/h가 10에서 16(1.6배)으로 늘 때 FP16S는 1.95배, FP16C는 약 4배 커졌습니다(FP16C는 잡음 포함).
- 결론: 정확도 경로는 FP32를 씁니다. 대역폭이 2배 들지만, h⁻⁴ 법칙 때문에 h는 2^(1/4) ≈ 1.19배만 굵어집니다. FP16은 고 레이놀즈수의 압력 항력에서는 영향이 다를 수 있습니다. 그래서 P2(Ahmed)에서 저사양 등급용 선택지로 다시 측정합니다.

- 2차 공간 보간과 2차 시간 보간은 개선이 없었습니다(전단파). 남은 접합면 오차는 보간 차수 때문이 아닙니다.
- **남은 약점**: 점성이 낮으면(τ = 0.52) 모서리 부근에서 O(h²) 원천 오차가 감쇠되지 않고 시간에 비례해 쌓입니다. TGV N = 32에서 한 감쇠 시간 뒤 상대 오차가 5 %였습니다(균일 굵은 격자는 0.015 %). 고스트의 비평형 성분을 속도 기울기로 다시 만들어도 줄지 않았습니다. P2(LES의 와점성, 고 Re 형상)에서 실제 영향을 측정하고, 필요하면 접합면 필터링을 도입합니다.

### P1b 저점성 접합면 오차 진단 (2026-10-29)
TGV, τ = 0.52, N = 32, 한 감쇠 시간. 해석해를 접합면에 주입하는 시험 장치(`refine.mjs`의 `oracleGhost`, `oracleCg`, 시험 전용)로 원인을 분리했습니다.

| 조건 | 상대 L2 오차 |
|---|---|
| 균일 굵은 격자 | 0.0148 % |
| N1C | 5.2 % (모서리 없는 띠에서도 6.1 %) |
| 고스트에 정답(모든 모멘트) | 0.106 % |
| 굵은 쪽 복원 칸에 정답 | 0.125 % |
| 둘 다 | 0.0167 % (= 균일 굵은 격자, 시험 장치 검증) |
| 복원 칸의 속도만 정답 / 밀도만 / Π만 | 0.128 % / 5.8 % / 1.7 % |
| 고스트의 속도만 정답 / 밀도만 / Π만 | 0.115 % / 8.3 % / 3.7 % |

- 오차는 매끄럽고(고주파 성분 4 %), 시간에 정비례해 자랍니다. 불안정이 아니라 일정한 원천입니다.
- 근원은 속도의 결합 루프입니다. 고스트 보간 오차가 고운 쪽 접합면 근처를 바꾸고, 복원이 그것을 굵은 쪽으로 다시 넘깁니다. 어느 한쪽을 정답으로 고정해 루프를 끊으면 오차가 사라집니다.
- 정확도를 높인 시도는 모두 실패했습니다. 고차 복원(3·4차 라그랑주)은 첫 스텝 오차가 40배 작았지만 장시간 23 %로 오히려 커졌습니다. 2차 공간 보간도 첫 스텝은 4배 정확했지만 오차가 더 빨리 자랐습니다. 2점 평균의 인공 확산(계수 h_f²/(8Δt) ≈ 0.031, 이 조건 물리 점성의 4.7배)이 루프를 일부 감쇠하고 있었던 것으로 판단합니다.
- 실용 판단: 같은 저점성 영역인 구 Re 100(굵은 단계 τ = 0.514)에서는 접합면이 기울기가 작은 곳에 놓여 세분화 Cd가 −0.01 %였습니다. 그래서 **배치 규칙**을 둡니다. 접합면은 물체에서 떨어진, 속도 기울기가 작은 영역에 둡니다(구 시험: 물체 중심에서 앞 1 D, 뒤 3 D, 옆 1.25 D 바깥). 근본 해결 후보(겹침 영역 결합, 복원 필터)는 차량 형상(P2·P4)에서 영향이 측정되면 착수합니다.

# V16 설계: (C) 차량 반사 개선 → (B) 벽면 LED 디스플레이

범위는 외관 전용입니다. 솔버·힘 계산·검증 경로는 건드리지 않습니다. 순서: C 먼저, B 나중.

## 현재 상태 (조사 결과)
- 반사 환경은 부팅 시 한 번 찍는 프로브 큐브맵 2개(`[0,2,0]`, `[0,2.4,7]`)뿐입니다. 캡처에는 터널 오브젝트(벽·조명·LED)만 들어가고 차는 들어가지 않습니다(`captureLightingProbes`, `src/engine/30-renderer-lighting.js`).
- 차량 클리어코트(거칠기 .06)는 이 큐브맵을 거의 거울처럼 반사합니다. 반사에 비칠 큰 발광 면이 천장 조명 몇 개와 LED 선뿐이라, 검은 차체는 4 % 프레넬 때문에 반사가 얇고 평평해 보입니다.
- 확산 조명은 같은 프로브의 SH9이며 `HQ.ambK`로 에너지가 맞춰집니다. 발광 면을 추가해도 전체 확산 밝기는 거의 변하지 않아야 합니다.

## C. 차량 반사 개선
**아이디어**: 자동차 촬영 스튜디오의 소프트박스를 쓴다. 장면에는 보이지 않고 **프로브 캡처에만** 들어가는 발광 면을 추가하면 모든 반사면(차체·휠·바닥)이 이를 반사합니다. 런타임 비용은 0(캡처 1회)입니다.

| 요소 | 위치(프로브 0 기준) | 목적 |
|---|---|---|
| 상부 키 스트립 | y 6.8, x ±4.5, z ±.45, 따뜻한 흰색, 복사휘도 ≈ 7 | 루프·보닛·펜더 위 긴 하이라이트 |
| 상부 플랭크 스트립 2개 | y 6.6, z ±2.2, 폭 .35, 차가운 흰색 | 지붕 가장자리·숄더 라인 |
| 측면 대형 패널 2개 | z ±4.8, y 1.4~3.2, x ±2.8, 차가운 흰색 ≈ 3.5 | 도어 패널의 부드러운 그라데이션 |
| 가장자리 | 각 면을 3겹 중첩(바깥일수록 어둡게) | 큐브맵 밉에서 계단·깜빡임 방지 |

**구현**: `captureLightingProbes`에서 프로브 0을 찍을 때만 절차적 메시(`bindMesh`)를 `drawMesh`로 그림(발광 = 알베도 × `surface.z`). 캡처는 `hdr/8`로 클램프되므로 최대 ≈ 8.
**검증 기준**: ① `hero_front34`·`side_long`·`rear34_low`에서 차체에 긴 하이라이트가 보임(전후 비교 이미지), ② 벽·바닥 전체 밝기가 눈에 띄게 변하지 않음, ③ 회귀 20/20·시네마틱 53/53·보행 10/10 유지, ④ 스튜디오 면이 장면에 직접 보이지 않음(캡처 전용).
**위험**: 확산(SH)이 약간 밝아질 수 있음 → `ambK`가 맞춰 주는지 확인하고 필요하면 복사휘도를 낮춤. 프로브 1(제어실)에는 넣지 않음.
**대안(채택 안 함)**: 차체 전용 실시간 평면 반사/SSR 강화(비용 큼), 노멀맵 플레이크(눈에 띄는 효과 작음).

## B. 벽면 LED 디스플레이
**위치**: −Z 측 벽 앞, 웨지 끝에서 안쪽 5.62 m, x −3.2~3.0, y 2.2~3.9의 얇은 패널(검은 베젤). 제어실이 있는 +Z 쪽에서 마주 보이고, 차를 보는 주요 구도에도 걸립니다. 같은 자리의 라이트 블레이드 1개는 비웁니다.
**표시 내용(캔버스 2D → 텍스처, 5 Hz 갱신)**: 시험 이름·상태, 풍속 U, 동압 q, Cd, Cl, 요각·차고, 최근 Cd 추이(미니 선 그래프), 해상도 등급과 "정성 표시" 문구. 값은 `LIVE.forces`·`__LIVE.U`·`__YAW` 등 이미 있는 값만 읽습니다(새 계산 없음).
**구현**: GLB 생성기에 `AETHER_WALL_DISPLAY`(UV 있는 쿼드)와 `DisplayScreen`·베젤 재질을 추가하고 엔진 재질 라이브러리에 같은 이름을 등록합니다. 텍스처는 기존 모니터 아틀라스 방식(`initMonitorAtlas`)을 따라 오브젝트 이름으로 붙입니다. 발광 재질이라 블룸을 받습니다.
**검증 기준**: ① 글자가 읽히는 캡처, ② 값이 풍속·요각 변경에 따라 바뀜(테스트), ③ 기존 검증기 통과, ④ 외부 요청 0.
**정직성**: 화면에 "LOW 격자 · 정성 표시 · 실측 아님"을 표기하고, 값은 솔버가 실제로 낸 것만 보여 줍니다. 값이 없으면 `–`.
**위험**: 텍스처 업로드 주기(5 Hz)와 캔버스 비용, 패널이 시네마틱·보행 경로를 막지 않는지 → 시네마틱 53/53, 보행 10/10으로 확인.

## 확인하지 못하는 것
SwiftShader 캡처로만 외관을 확인합니다. 실제 GPU·iPhone 성능과 실제 화면에서의 색 느낌은 이 환경에서 검증할 수 없습니다.

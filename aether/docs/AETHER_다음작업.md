## 1. 현재 구조 한눈에 보기

| 층 | 무엇을 하나 | 실제 물리 계산인가 |
|---|---|---|
| 실시간 GPU CFD (신규, 기본값) | 풍동 전체를 격자로 나눠 비압축성 유동 방정식을 매 프레임 계산 | 예. 단, 점성·난류 모델 없는 오일러 근사 |
| 연기 (신규) | 같은 유동장이 운반하는 수동 스칼라(염료)를 레이 마칭으로 렌더 | 예. 연기는 계산된 속도장으로만 이동 |
| 차량·팬·사람 | 차량은 복셀 고체, 팬은 바람을 내보내는 구동 영역, 사람은 매 프레임 갱신되는 이동 고체 | 예. 경계조건으로 방정식에 들어감 |
| 기존 CPU 솔버 (원본) | 32³/64³ 진단용 | 계산은 실제지만 2스텝(0.017초)만 돌아 유동이 거의 0이었음 |
| 기존 필라멘트·입자 | 실시간 CFD를 끄면 대체 표시 | 사람 효과는 해석식 근사(교과서 모델) |

### 실시간 CFD 알고리즘

1. 속도 이류: 세미 라그랑주 역추적, 삼선형 보간
2. 와도 보존력(vorticity confinement): 수치 확산으로 사라지는 소용돌이를 일부 복원. 물리 법칙이 아니라 보정항
3. 발산 계산 → 야코비 반복 32회로 압력 포아송 방정식 풀기 → 압력 기울기를 빼서 발산 0으로 투영
4. 연기: MacCormack 이류(세미 라그랑주보다 선명), 이웃 최소·최대로 클램프
5. 경계조건: 입구 균일류 U, 출구 압력 0, 바닥 이동 벨트(U), 천장·측벽 미끄럼, 고체 내부 속도 = 고체 속도

| 품질 | 격자 | 셀 수 | 셀 크기 |
|---|---|---|---|
| HIGH (PC 기본) | 176×56×80 | 78.8만 | 약 10cm |
| LOW (모바일 기본) | 112×36×52 | 21.0만 | 약 16cm |

주소 뒤에 `#q=LOW` 또는 `#q=HIGH`를 붙이면 강제로 지정할 수 있습니다.

## 2. 이번 버전에서 확인된 것 (헤드리스 Chromium + WebGL2 실측)

- LOW 격자, 풍속 5 m/s, 모의시간 약 1.2초 시점 측정
- 차량 상류: 5.05 m/s로 입구 풍속 유지
- 차량 바로 뒤: −0.18 m/s로 역류(재순환 영역) 발생
- 차량 5.5m 뒤: 3.08 m/s로 후류 속도 손실
- 발산 잔차: RMS 기준 U/h 대비 0.5%로 질량 보존 양호, 최대값은 고체 경계 근처에서 47%로 큼
- 차량 복셀화: 약 0.16초
- 측정 방법: 브라우저 콘솔에서 `__LIVE.api.read(x,y,z)`, `__LIVE.api.divStats()`

주의: 헤드리스 환경은 CPU로 GPU를 흉내 내므로 매우 느립니다. 실제 GPU에서의 프레임과 화면 품질은 직접 확인이 필요합니다.

## 3. 알려진 한계 (정직한 목록)

1. 점성과 난류를 풀지 않음: 레이놀즈 수, 박리 위치, 항력계수는 신뢰할 수 없음. 흐름의 모양(갈라짐, 후류, 역류)만 정성적으로 의미 있음
2. 격자 해상도 10~16cm: 사이드미러, 윙 끝단, 바퀴 디테일은 복셀 계단으로 뭉개짐
3. 야코비 32회는 완전 수렴이 아님: 고체 경계 근처 발산 최대값이 큼
4. 속도·압력을 같은 위치에 두는 격자(collocated): 체커보드 압력 모드가 생길 수 있음
5. 바퀴 회전 무시, 바닥 전체가 벨트처럼 움직인다고 가정
6. 연기가 풍동 안의 일부 장비(계단, 롤링로드 기계)를 뚫고 보일 수 있음. 차·팬·사람만 가림 처리
7. 차량 에셋 재배포 권리 미확립: 상업 게시 전 반드시 교체 또는 권리 확인
8. 파일 16MB 단일 HTML: 편집·버전 관리가 어려움

## 5. 작업별 지시 방법 (Claude에게 그대로 붙여 넣기)

### 5-1. 실행 확인 (가장 먼저)
```
AETHER_WIND_TUNNEL_SHOWCASE.html을 PC 크롬에서 열었고 결과는 [스크린샷/증상]이야.
상단 왼쪽 "실시간 GPU CFD" 상태줄 내용은 [내용]이야. 문제 있으면 원인부터 찾아줘.
```

### 5-2. 멀티그리드 압력 솔버
```
AETHER 실시간 CFD의 야코비 32회 압력 솔버를 V-cycle 멀티그리드로 바꿔줘.
조건: 아틀라스 텍스처 구조 유지, 고체 셀 노이만 조건 유지, 출구 디리클레 유지.
검증: __LIVE.api.divStats()의 relMax를 변경 전후로 헤드리스에서 측정해서 표로 보여줘.
```

### 5-3. 항력계수
```
차량 복셀 표면에 닿는 압력을 적분해서 항력·양력을 계산하고 Cd, Cl을 HUD에 표시해줘.
기준 면적은 차량 정면 투영면적을 복셀로 계산해서 쓰고, 한계(비점성 계산이라 마찰항력 없음)를 화면에 명시해.
```

### 5-4. 검증 벤치마크
```
차량 대신 원기둥(지름 0.5m) 하나만 넣는 테스트 모드를 추가하고,
후류 한 점의 횡방향 속도 시계열로 스트라우할 수를 구해서 문헌값 0.2와 비교해줘.
```

### 5-5. 파일 분리
```
단일 16MB HTML을 index.html, engine.js, live-cfd.js, ui.js, assets/vehicle.glb, assets/fan.glb로 분리해줘.
기능 변경 없이 분리만 하고, 분리 전후 동작이 같은지 헤드리스로 확인해.
```

## 6. 검증 습관 (매 작업 공통)

1. 수정 전후로 같은 측정: `__LIVE.api.read(-3.5,2.8,2.8)`(상류), `read(3.0,0.6,0)`(후류), `divStats()`
2. 셰이더는 glslangValidator로 컴파일 확인
3. 헤드리스 Chromium(SwiftShader)으로 부팅·오류 확인. 단, 성능 판단은 실제 GPU에서만
4. 새 기능은 "실제 계산 / 근사 모델 / 연출"을 화면과 문서에 구분 표기

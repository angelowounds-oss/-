# CHANGELOG

## 0.14.0-dev

### 시네마틱 디렉터 (첫 입장 30초 연출 재설계)
- **기존 구조의 결함**(첨부본에서 재확인): ① `wowStart/wowTick`(30 s 키프레임)과 `cine()/script`(37 s 자막·프리셋 버튼 클릭)이 별개 시계로 동시에 존재, ② `cine()`은 `LIVE.ok`이면 wowStart를 건너뛰어 GPU 유동이 정상일 때 키프레임 카메라가 아예 재생되지 않고 script가 프리셋 버튼을 `click()`으로 눌러 시점만 바꿈, ③ wowTick은 매 경유점에서 smoothstep으로 감속·정지·재출발, ④ 종료/취소 후 남은 setTimeout이 뒤늦게 시점을 바꿀 수 있었음, ⑤ 10 s에 `camera.cutaway`로 벽·유리를 갑자기 숨김.
- **단일 제어기** `src/engine/89b-cinematic.js`(`window.__CINE`): 상태 IDLE→PREPARING→PLAYING→FINISHED, 활성 상태→CANCELLED. 카메라·자막·진행 표시가 하나의 누적 시계(프레임 시간, 프레임당 최대 0.25 s)를 쓰고 타이머는 없음. 첫 입장과 "시네마틱 재생" 버튼은 같은 `CINE.start()`. 프리셋 버튼 `click()` 우회 제거(재생 상태 전환은 `smokeSetPlaying` 직접 호출).
- **준비와 촬영 분리**: PREPARING 동안 첫 구도에서 대기하며 촬영 시간을 쓰지 않음. 조건 = 렌더러 준비 + GPU 성능 측정 완료 + 시뮬레이션 시간 ≥ 3 s(연기가 레이크→후류까지 도달). 입장 화면 버튼도 같은 조건으로 활성화("GPU 성능 측정/연기 흐름 형성 N %"), 25 s 초과 시 허용. PREPARING 15 s 초과 시 경고 기록 후 재생. GPU 유동 실패(`LIVE.err`)여도 카메라는 재생(기존 32³ CPU 진단 연기로 대체). 유동장·풍속·팬 속도는 건드리지 않음(기존 wowStart의 풍속 1 m/s 설정과 S3 진단 자동 시작 제거).
- **실측 좌표 기반 경로**: 차체 메쉬 경계 상자를 `vehicleModel()`로 월드 변환, 앞·뒤는 `FLOW_LAYOUT`(유동 +X, 코 −X 검증됨), 리어 스포일러는 후방 1/4에서 가장 높은 정점들의 경계(추정, `wing.estimated`). 모든 시점이 풍동 내부(벽 안쪽)에 있어 cutaway·벽 숨김 불필요(재생 중 `camera.cutaway=false` 고정).
- **속도**: 위치 경로는 centripetal Catmull–Rom, 호장 표(구간당 48샘플)로 거리→파라미터 대응, 시간→거리는 단조 3차 Hermite(PCHIP) — 시작·끝에서만 속도 0, 중간 경유점은 속도>0. 주목점은 별도 경로(같은 진행도). 화각은 시각 영역 기준 40°(후반 46°), 시네마 띠(18 %)와 화면비(16:9·21:9 최대 가로 70°·세로 9:16 가로 46°)를 반영해 전체 투영 화각 계산. 세로 화면은 별도 주목점 경로와 가로·세로 경로 가중 전환(회전·리사이즈에도 점프 없음).
- **취소·건너뛰기·복구**: 캔버스 pointerdown/wheel/touchstart·프리셋·보행·비상정지·컨텍스트 손실이면 즉시 CANCELLED(현재 자세 보존, 궤도 중심은 시선 방향으로 ≥3.2 m 앞으로 정리). "건너뛰기 ›" 버튼/Esc는 최종 구도로 컷(TAA·연기 이력 `FX.reset`). 컷에서만 이력 초기화, 연속 이동 중에는 초기화 안 함. 탭 숨김 후 복귀 시 시계 재설정.
- 시네마틱 동안 도크·툴바·HUD를 숨기고 얇은 진행선과 건너뛰기 버튼만 표시. 자막은 단일 타임라인(격자 수는 실제 `LIVE.N`에서 계산).
- 검증: `tests/cinematic.mjs`(정적 5 + 시나리오 + 경로 수치 + 화면비별 구도 + 6시점 스크린샷), 결과 `tests/out/cine/`.

### 시작 GPU 측정 수정 (사용자 PC 로그에서 발견)
- 사용자 PC(Intel UHD 630, Chrome 151, ANGLE/D3D11)의 `chrome://gpu` 로그에 측정 구간(약 2.5 s)에만 `glReadPixels: Invalid format and type combination`이 반복됨. 원인: GPU 동기화용 1×1 읽기가 **현재 바인딩된 프레임버퍼**를 `RGBA/UNSIGNED_BYTE`로 읽었고, 그 순간 바인딩된 것이 실수(float) 타깃이면 엄격한 드라이버가 거부 → 동기화가 안 되어 GPU 시간이 실제보다 훨씬 작게 측정되고 등급이 과도하게 높게 선택될 수 있었음(느림의 유력한 원인).
- 전용 1×1 RGBA8 프레임버퍼로 읽도록 교체(`perfFence`). 검증: `tests/fence.mjs` — 수정 전 빌드 잘못된 읽기 4회 + GL 오류 1건, 수정 후 0회·0건.
- 엔지니어 패널 상태 줄에 사용 중인 GPU 이름(`GPU: …`) 표시.

### S3 CPU 진단 64³ 수정
- 64³를 고르면 계산 시작 전 `INIT / OUTLET_DISCONNECTED`로 중단되던 문제: 64³에서는 차량 프록시의 얇은 껍질이 해상되어 차체 내부·닫힌 공간이 "출구와 이어지지 않는 유체 셀"로 남고, 기준 솔버가 이를 오류로 거부함(32³는 해상도가 거칠어 메워져 문제없었음). 워커(`assets/s3-worker.js`)에서 격자화 직후 출구에서 닿지 않는 유체 셀을 고체로 봉합하고 개수를 보고서(`sealedCells`)에 기록.
- 상태 문구의 "32³" 고정 표기를 선택한 해상도로 수정. 64³ 측정: 초기화 1.0 s, 스텝당 약 21 s(헤드리스 CPU 에뮬 환경 기준, 32³는 스텝당 약 1.7 s).

### 사용자 피드백 반영 (화질·연기)
- **엔지니어 패널 "화질 · 해상도"**: 전체 등급·화면 해상도(50~150 %)·연기 품질·그래픽·CFD 격자·자동 조절을 직접 선택. 저사양 기기도 모든 등급 선택 가능(측정 추천보다 높으면 경고). 선택은 브라우저에 저장.
- **연기 레이크 실물화**: 팬 앞 30 cm 허공에서 나오던 연기를 팬 앞 0.6 m 스테인리스 레이크(세로 막대 7노즐 / 가로 막대 9노즐)의 노즐 끝에서 나오게 변경. 노즐 반경 8.5 cm → 연기 격자 0.75칸(LOW 약 5.6 cm)으로 줄여 줄기가 한 장의 판으로 합쳐지지 않게 함.

### M4 마무리 — 검증 전 항목 PASS
- **발산 점검 수정**: 투영 후 발산 계산이 출구 면(p=0 경계)에서 투영 전 유속을 복사해 쓰고 있었음. 투영이 출구 면 유속(영기울기 예측 + p=0 유령 셀 기울기)을 속도 텍스처 w 채널에 저장하고 점검이 그 값을 사용. 원기둥 8셀/D 발산 RMS 2.8e-3(전부 출구 열) → 1.7e-6. 흐름 계산은 동일.
- **반축 조대화 멀티그리드**: 4셀 이상이고 가장 고운 축보다 1.5배 이상 굵지 않은 축만 절반으로. 준2D 검증(스팬 4셀)이 2단계 → 4단계. 풍동·구 격자는 단계 구성 동일. 원기둥 잔차 1.2e-3~3.6e-3 → 1.7e-4~5.3e-4.
- **경계 처리 vf 채택**(Kajishima 2001 체적분율 강제): 부분 고체 면 속도를 u←(1−χ)u+χus. cut만 쓰면 부분 셀 접선 속도가 고체를 느끼지 못해 구 8셀/D 검사체적 Cd −52 %. vf는 솔버 힘 −0.7 %, 검사체적 −16.7 %.
- **검사체적 운동량 수지 항력**(검증용): 경계 처리·힘 공식과 독립인 교차 확인.
- **St 추정**: Cl 상승 영교차 평균 주기(30시간단위 창의 DFT 분해능 0.033 문제 해결).
- 연기 고체 판정을 속도 셀 최근접 → 부분체적 φ 삼선형 보간으로(차량 주변 15 cm 계단 모양 제거).
- HUD: 차량 Cl "차 밑 틈이 셀보다 작아 신뢰 낮음" 표기, 힘 계산 방식 표기.

### M7 LBM 비교

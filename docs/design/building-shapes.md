# 건물 형태 변주 계획 (2026-10-10)

사용자 피드백: 외관이 "종이에 그린 그림" 같다 → 질감·입체감(RND-06, 완료 1단계) 다음 과제는 **모양 자체의 단조로움**이다.
이 문서는 계획이다(구현 전). 티켓은 `docs/backlog/WLD.md`의 WLD-06~12.

## 1. 현황 (코드 조사)
- 도시 건물 560동: 입장 가능한 일반 건물 384, 원경(far) 120, 랜드마크 모델 56. 이 계획의 대상은 **일반 384동**.
- 높이 분포: 30 m 미만 62 · 30~60 m 183 · 60~100 m 74 · 100~150 m 44 · 150 m 이상 21 (평균 약 16층).
- 모든 일반 건물이 같은 구조: **받침(podium, 6~13 m) + 탑(tower, 직사각형, 받침보다 1.5~5 m 안쪽) + 선택적 왕관(crown, 125동)**. 옥상에 상자 소품·안테나·광고판.
- 모양의 차이는 사실상 **텍스처 스타일 4종(87/100/91/106동)과 색**뿐이고, 윤곽은 전부 직육면체다. 그래서 하늘 선이 단조롭다.
- 생성 순서 주의: `buildWorld`가 하나의 난수열(`rnd`)로 건물을 차례로 만든다. 건물 모양에 난수를 더 쓰면 **이후 모든 건물의 위치·높이가 바뀌고** 저장된 폐허·문 상태(건물 번호 기준)가 어긋난다 → 모양은 **건물 seed에서 파생한 별도 난수열**로만 정한다.

> 2026-10-10 추가: 1000 m 초고층 한 동(`SKY APEX 1000`, WLD-13)이 먼저 들어갔다. 현재는 직육면체 한 덩어리이며, WLD-07(다단 후퇴)·WLD-08(왕관) 적용 시 첫 대상으로 삼는다. 단계 일반화(WLD-06) 때 `lot.landmark`·`lot.express`·`world.skyTower`를 `stages`로 옮겨야 한다.

## 2. 구조적 제약 (무엇이 모양을 묶고 있나)
| 소비처 | 가정 | 모양 변주 시 영향 |
|---|---|---|
| `building.js plan()` | 층 목록 = 받침 층들 + 탑 층들 + 지붕. **층마다 `rect`를 가진다**(`L.rect`) | 층마다 직사각형이 달라지는 것(후퇴)은 이 추상화로 대부분 처리 가능 |
| `building.js` 일부 | 탑 하나(`this.tow`)를 직접 참조: 엘리베이터·계단 코어 위치(`tow.x0/z0` 모서리), 지붕 소품(`tow.x1/z1`), 가림막 충돌체(`updateSolid`) | 코어가 모든 단계에 들어가야 함, 지붕 소품은 **최상단 단계** 기준으로 |
| 외관 인스턴스(`world.js`) | 건물당 연속 인스턴스 2~3개(`tierIdx`, +1, +2) | 단계 수가 가변이면 목록(`stageIdx[]`)으로 일반화 필요 |
| `relief.js`, `blaze.js` | 위와 같은 `tiers`·`tierIdx+1/+2` 가정 | 둘 다 단계 목록을 돌도록 수정 |
| 충돌체 `lot.solid` | 건물 전체 박스 하나(열면 층별 박스로 대체) | 후퇴 형태는 단계별 박스 |
| 내부 생성(방·가구·AI·길찾기) | 층 단위 직사각형 | **직사각형 층이면 그대로 동작.** 비직사각형(ㄱ자·모서리 깎기)은 방 배치·벽·내비·벽 파괴·붕괴 전부 재작업 |
| 테스트 | `floor-population`, `breach`, `entrance-holes`, `cull-identity`, `building-fire`, `facade-relief` | 단일 단계 건물은 **픽셀·동작 동일**해야 한다(회귀 기준) |

핵심 결론: **"층마다 직사각형이 다른" 변주는 안전하고 값이 크다. "층 평면이 직사각형이 아닌" 변주는 비싸다.** 계획은 전자를 먼저, 후자는 조사 후 결정한다.

## 4. 구역별 원형(archetype) — 모양에 의미를 주기
구역(`ZONES`)과 용도(`KINDS` 호텔/사무/주거)에 따라 변주 규칙을 다르게 한다.
| 구역 | 분위기 | 모양 규칙 |
|---|---|---|
| 금융 지구 | 유리 사무 타워 | 높고 가늘다, 2~3단 후퇴, 뾰족/유리 왕관, 아케이드 받침 |
| 네온 구역 | 복합 상가·유흥 | 중간 높이, 수직 핀·큰 간판 옥상, 발코니, 좁은 별관 |
| 차이나 블록 | 전통풍 + 밀집 | 낮고 넓다, 계단식 처마(층마다 얇은 지붕 띠), 붉은 기둥 받침 |
| 산업 지구 | 공장·창고·아파트 | 판상형 상자, 물탱크·굴뚝·톱니 지붕, 후퇴 없음 |
| 중앙 광장 | 랜드마크 혼합 | 모든 원형 + 쌍둥이 탑, 2~3동은 B 계열 후보 |
용도 보정: 주거는 발코니·판상형, 호텔은 캐노피·네온 왕관, 사무는 유리·후퇴.

## 5. 설계 원칙 (불변 조건)
1. **결정론**: 모양 = f(건물 seed, 구역, 용도). 같은 건물은 항상 같은 모양. 난수열은 건물별로 따로 만들어 기존 건물 위치·높이가 그대로.
2. **회귀 동일성**: 단계 1개짜리(변주 없음) 건물은 기존과 **픽셀·동작 동일**. 리팩터링 단계(WLD-06)는 이것을 테스트로 증명하고 나서 변주를 켠다.
3. **내부 호환 규칙**: 단계의 직사각형은 서로 포함 관계, 변의 길이 ≥ 13 m(방·복도가 들어가는 최소), 엘리베이터·계단 코어 모서리(`x0+0.5, z0+0.5`부터 약 7×6 m)는 **모든 단계 안에** 있게 줄이는 쪽을 `x1/z1`(코어 반대편)으로 한정.
4. **플레이 중 셰이더 컴파일 0**(ADR-0002): 새 모양은 기존 외관 인스턴스·relief·파티클만 사용, 새 재질은 시작 시 장면에 있어야 한다.
5. **예산**: 삼각형 +10% 이내(첫 화면), 드로우콜 +2 이내. 실기기 측정(PERF-02) 전에는 relief처럼 거리 제한·그림자 제외를 기본으로.
6. **파괴·화재 호환**: 단계 목록을 `blaze.js`(발화·붕괴 애니메이션), `relief.js`가 그대로 순회한다. 붕괴 테스트에 다단 건물을 포함.

## 6. 데이터 모델 (WLD-06)
```
lot.stages = [ { kind:'podium'|'tower'|'crown'|'annex', x0,z0,x1,z1,y0,y1, style, inst:<외관 인스턴스 번호>, enterable:bool, roofKind? } ... ]
lot.tiers  = 기존 필드를 stages에서 계산하는 호환 getter(podium, tower(가장 아래 탑), crown) — 한 번에 걸쳐 바꾸지 않고 소비처를 순서대로 이행
```
- `Building.plan()`은 `stages`를 순회해 `levels`를 만든다(층마다 `rect`). `tow`는 "코어가 있는 가장 아래 탑 단계".
- 외관 인스턴스 목록과 `tierIdx`는 `stage.inst`로 대체. `relief`·`blaze`는 `lot.stages`를 순회.

## 8. 검증 계획
- **구조 테스트 `building-shapes`**: 모든 일반 건물에 대해 (a) 단계 직사각형이 포함 관계, (b) 최소 변 ≥ 13 m, (c) 코어 사각형이 모든 단계 안에, (d) 단계 높이가 이어짐, (e) 이웃 건물과 겹치지 않음, (f) 같은 seed → 같은 모양(결정론), (g) 원형 분포(구역별 후퇴 비율 등).
- **기능 회귀**: `floor-population`, `breach`, `entrance-holes`, `building-fire`(붕괴·재건), `facade-relief`, `cull/pack/light-skip`, `no-runtime-compile`.
- **시각**: 상공·거리·야간 컨택트 시트 전/후(WLD-12 도구), 스카이라인 실루엣 비교.
- **성능**: 첫 화면 삼각형·드로우콜(`boot`), 건물 열 때 층 생성 시간(`floor-population`)이 변주로 늘지 않는지.

## 10. 결정이 필요한 것 (권고안 포함)
1. **범위**: A 계열(직사각형 호환)만 하고 B는 조사 후 결정 — **권고: 예**. 이유: 효과 대비 비용이 크게 다르고, B는 내부·파괴·AI 전부를 건드림.
2. **테라스 입장 가능 여부**: 후퇴로 생긴 아래 단계 지붕 위를 걸을 수 있게 할지 — **권고: 1차는 시각만**(충돌체는 낮은 난간), 다음 단계에서 걸을 수 있게(헬기장·옥상 파쿠르와 연결).
3. **쌍둥이 탑의 별관**: 입장 가능 vs 비입장 — **권고: 비입장**(받침을 통해서만 본관으로 들어감). 입장은 별도 티켓.
4. **구역별 원형**(4절 표): 이 방향으로 가는지, 다른 취향(예: 한국 도시 특징 강조, 사이버펑크 과장)이 있는지.
5. **삼각형 예산**: 첫 화면 +10% 이내가 괜찮은지(실기기 데이터가 없어서 보수적으로 잡음).

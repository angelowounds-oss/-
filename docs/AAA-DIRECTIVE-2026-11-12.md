# AAA 진화 지침서 (2026-11-12) — 코드 전수 분석과 작업 지휘안

대상: 브랜치 `feat/WLD-24a-procedural-buildings`, 커밋 `885275a`.
성격: **수정이 아니라 지휘.** 어디를, 어떻게, 어떤 순서로, 무엇으로 증명하며 바꿀지를 적는다. 작업자(사람이든 세션이든)는 이 문서의 티켓 하나를 받아 간다.

근거는 셋이다.
1. 코드 전수: `src/` 126파일 23,597줄(생성 데이터 파일 포함), 굽기 파이프라인 `build/world/` 5,710줄, 테스트 44 단위 + 72 e2e. 파일별 역할·규모는 부록 A.
2. 오늘 측정(부록 B): 부팅 직후 JS 힙 2,089 MB, 전체 GC 0.66~0.90 s, 도로 97,634선·표본 372만 개, 자동 주행 그래프 노드 367만 개, 1:1 도로 교통의 신호 참조 0건.
3. 기존 문서: `REVIEW-2026-11-08.md`(평가), `AAA-PLAN.md`(2026-10-27 화질 계획), ADR-0044(다중 지역), `IMPROVEMENTS-2026-11-11.md`(배치 보완). 이 문서는 그것들을 대체하지 않고 **위에 선다**(부록 C에 관계를 적었다).

**실기기 GPU 수치는 여전히 0이다.** GPU에 관한 목표는 전부 "사용자 실기기 검수 조건"이고, 이 컨테이너(SwiftShader)에서는 JS 시간·할당·드로우콜·삼각형만 잰다(CLAUDE.md).

## 1. 진단

### 1.1 한 줄

**현실 자료(1:1 국토, 실제 도로 97,634선, 실제 건물 47만 동, 가로 시설 137만 개)는 AAA급으로 들어왔다. 그것을 "움직이는" 층 — 차량 역학, 교통·보행 AI, 빛과 그림자, 소리, 할 일 — 은 아직 프로토타입에서 동작 단계 사이다. 그리고 모든 것 밑에 2 GB JS 힙이라는 구조적 병목이 있다.**

### 1.2 스코어카드 — 현재와 AAA 문턱

## 2. 코드 전수 분석 (시스템별)

각 절은 ① 구성 ② 있는 것 ③ 없는 것·현실과 어긋난 것(근거) ④ AAA에서 요구하는 것 순서다.

### 2.1 기반: 프레임 루프 · 메모리 · 스트리밍

**구성.** `main.js`(103) rAF 루프 → `game.js`(2,104) `update`가 8단계(`플레이어·차량·사람·규칙·세계·카메라·HUD·렌더`, `game.js:441~453`)를 격리해 돈다(PERF-03). 물리는 `physics.js`(284) Rapier 0.21 고정 60 Hz, 최대 4회 하위 스텝, 보간(ADR-0003). 월드 자료는 `chunkstore.js`/`bakedload.js`(ADR-0013 청크 컨테이너) → `region.js`(215, 지역 목록 `regions()`), `roadnet.js`(299, `net()`이 도로를 한꺼번에 든다), `heightmap.js`(16 m 높이 타일 스트리밍), `farland.js`(206, CPU 클립맵), `realbuildings.js`(255, 512 m 타일), `streetscape.js`(553, 가로 타일), `forest.js`(219, 32 m 칸 바이트).

**있는 것.** 단계 격리와 오류 기록(`errors.js`). 높이·건물·가로·식생은 타일 스트리밍이다. 청크 컨테이너와 시·도별 파일(ADR-0036). 저장 스키마·백업(SAV). 자동 품질과 동적 해상도(`engine.js setScale`).

**없는 것 · 어긋난 것.**
- 지역 래스터(수도권 1,934만 칸)와 도로망 전체가 `core` 청크로 부팅 때 올라온다. ADR-0044가 잰 비용: 경기 하나 더하면 `core.pak` 336 MB, 렌더러 4.1 GB, 전국은 래스터만 약 7 GB.
- JS 힙 2 GB(1.3절). PERF-BASELINE §B의 "힙 50~65 MB"는 1:1 이전 값이라 더는 맞지 않는다.
- 할당 700 KB/프레임, 승격 89 KB/프레임(2026-10-09 측정, PERF-04 미착수). 1:1 이후 재측정 없음.
- 로드 6.4 s(이 컨테이너, `farland` 기준 1.5 s 실패), 부팅 약 90 s(SwiftShader라 절대값 무의미).
- 다른 도시 첫 진입 끊김 1,273 ms(`cities` 실패, REVIEW §4).
- 렌더러 메모리가 업데이트마다 약 4 MB 쌓이고 태스크 사이에서만 풀린다(PERF-07, 원인 미확정). 택시 한 경로에서 5~8 GB(REVIEW §4).
- 부동 원점 없음: 원점에서 325 km(부산)는 float32 한 칸 3 cm(WLD-23c).

**AAA 요구.** 플레이어 주변만 메모리에 있고 나머지는 디스크에 있다. 힙은 수백 MB, 메이저 GC 멈춤 한 자리 ms, 10분 주행에 50 ms 넘는 프레임 0. 부팅 10~15 s. 좌표는 부동 원점.

### 2.2 물리 · 차량

**구성.** `physics.js` `PHYS = { dt 1/60, gravity −9.81, mass 1300, eta 0.85, rho 1.2, absK 0.97, engineBrake 0.35, springK 15.1 }`, `createVehicle`(Rapier `DynamicRayCastVehicleController`, 질량·관성·무게중심 −0.42 m, 스프링 1.24 Hz), `driveVehicle`(엔진 힘 = min(발진 한계, 출력/속도), 제동 임펄스 = 접지력·ABS, 공기·구름 저항, 젖은 노면 `wetGrip`). 제원은 `carspecs.js`(세단·스포츠·SUV·트럭·로드스터: 질량·출력·접지 계수·항력 면적·구름 저항). `vehicle.js`(509): 조향 감쇠, 손상(`hp`, 정점 변형 `dent`), 연료(`FUEL`, 거리 기준), 물(얕은 물 항력·부력·침수·침몰), 충격 판정, AI 운전(`driveAI`, 순수 추종). `character.js`(82) Rapier 운동학 캐릭터 컨트롤러. `ragdoll.js`(543) 12강체 랙돌(힌지·구 관절, 일어나기). `craft.js`(359) 헬기·보트, `warcraft.js`(343) 전투기·다크스타, `military.js`(390) 전차.

**있는 것(실측으로 지킨 값).** 세단 0→100 km/h 7.9 s, 최고 209 km/h, 100→0 제동 41.6 m(비 57.7 m), 횡가속 0.81 g, 낙하 9.81 m/s², 낙하 착지·탑승자 부상·폭발 밀림·연료·열차 충돌·파손 성능 저하(PHY-05/06, `physics-reality`, `physics-extra`). 포탄 1,100 m/s 탄도, 전투기 에너지 모델 9 g 제한, 헬기 자동회전.

**없는 것 · 어긋난 것.**
1. **타이어 모델이 없다.** 횡력은 Rapier 컨트롤러의 마찰 슬립 하나(`setWheelFrictionSlip`)이고, 그 위에 `vehicle.js:248~251`이 횡속도를 지운다. 슬립각·슬립률 곡선, 하중 이동에 따른 접지력 변화, 언더/오버스티어, 리프트오프, 카운터스티어가 없다. 드리프트는 핸드브레이크 때만(`handSlip 0.5`).
2. **동력계가 없다.** 기어·변속·엔진 토크 곡선·회전수가 없다. 엔진 힘은 `min(발진 한계, P/v)`의 이상 곡선. 엔진음의 `rpm`은 속도에서 만든 0..1 대리값(`audio.js:175`).
3. **노면별 마찰이 없다.** 풀·흙·자갈·젖은 노면 중 젖은 노면만 있다(REVIEW §3.7 "고치지 않은 것").
4. **서스펜션 기하가 없다.** 캠버·토·안티롤바·범프스톱 없음. 롤·피치는 강체 결과 그대로(`vehicle.js:44`의 `pitch/roll`은 표시용).
5. **조향이 단순하다.** 애커만 없음, 속도 비례 최대 조향각만(`maxSteerNow`). 파워스티어링 느낌·셀프 얼라이닝 토크 없음.
6. **제동 배분·ESC 없음.** ABS는 상수 `absK 0.97` 한 줄.
7. **이륜차는 기울지 않는다**(`moto`는 연료 표에만 있다; 모델·역학 확인 필요).
8. **보행 물리.** 캐릭터 컨트롤러는 경사·계단(autostep) 설정값을 확인하지 못했다(EV-10에서 측정). 비탈 보행 속도는 Tobler로 맞췄다(NPC).
9. **캐릭터–차량 충돌**은 OBB 밀어내기 우회(PHY-02).
10. 총기는 즉시 명중(탄도 없음). 설계 결정 대기.

**AAA 요구.** 슬립 기반 타이어 모델(간이 Pacejka 또는 브러시 모델)과 하중 이동, 토크 곡선·기어비·변속 로직(자동), 노면 재질별 마찰·구름 저항, 롤 강성(안티롤), 애커만, ABS/TC/ESC 토글, 이륜차 기울기, 트레일러(트럭), 손상이 역학에 영향(이미 일부). 모든 값은 실차 제원 범위 안이고, 스키드패드·슬라럼·ISO 3888 회피·제동 테스트로 증명한다.

8. 전투 AI: 분기와 상수(AI-01). 제압 사격·연막·엄폐 이동 계획·분대 역할 없음.
9. 사회 반응의 폭: `docs/design/action-catalog.md`의 ○ 항목(ATM 탈취, 금고, 인프라 교란, 소방, 인질…).

**AAA 요구.** 교통은 "규칙 + 성향 + 반응"이다. 신호·정지선·우선권·차로 변경·합류·추월·양보·주차 진출입·사고 회피·플레이어 반응(경적·급제동·피함), 등급·시간대별 밀도, 운전자 성향 분포. 보행자는 횡단보도·신호·군중·대피·목격. 경찰은 단계별 전술. 전투는 유틸리티 AI와 분대. 측정은 "10 km 자동 주행 중 신호 위반·추돌 수"처럼 숫자로.

## 4. 작업 패키지 (EV 티켓)

형식은 `docs/backlog/README.md`와 같다. 각 티켓: 목적 / 현재(근거) / 목표(AC) / 어디·어떻게 / 검증 / 크기·의존 / 흡수하는 기존 티켓.
트랙: **F** 기반 · **P** 물리 · **A** AI · **W** 월드 · **R** 렌더 · **C** 캐릭터 · **S** 소리 · **G** 게임플레이 · **U** UX · **Q** 품질·구조.

### F. 기반 (EV-01 ~ EV-09)

#### EV-01 지역 래스터 스트리밍 — P0 · L · Phase 0
- 목적: 전국을 열 수 있는 유일한 길. ADR-0044 2단계 "스트리밍(필수)".
- 현재: 지역 래스터가 `core` 청크에 통째로(수도권 1,934만 칸, 경기 7,647×10,041칸). 렌더러 4.1 GB.
- 목표(AC): core에는 메타 + 128 m 거친 래스터만. 2,048 m 타일(`reg/<조각>/<i>_<j>`, 129×129 h·water·level·own)을 플레이어 주변 8 km 선적재, LRU 해제. 부팅 힙에서 래스터 몫 ≥ 90% 감소. 경기+수도권 빌드에서 `province-probe` 통과, 렌더러 ≤ 2.5 GB.
- 어디·어떻게: `build/jobs.mjs`·`bake.mjs`에 `reg/` 작업 추가(`heightmap.js`의 높이 타일 방식 재사용). `src/region.js`: `regionHeight/Weight/Water`가 타일 캐시 → 거친 래스터 순으로 읽는다. 순간이동·부팅은 주변 타일 도착까지 대기(`transit.js`, `main.js` 로딩). 지역 함수를 부르는 12파일(IMPROVEMENTS §4.4 25b 목록) 영향 확인.
- 검증: `unit/world-region`(수치 동일), `e2e/province-probe`, 새 `heap-gate`.
- 의존: 없음. 흡수: WLD-25b 2단계, PERF-05 일부.

#### EV-02 도로망 SoA와 타일화 — P0 · L · Phase 0
- 목적: 힙 2 GB의 가장 큰 몫을 GC 대상에서 빼고, 도로도 스트리밍한다.
- 현재: `roadnet.js net()`의 `r.pts = [[x, z], …]` 372만 배열, `N.grid` Map 63,658칸, 도의 도로선이 `pts`로 한 번 더(인코딩만 423 MB, ADR-0044).
- 목표(AC): 도로 표본은 `Float32Array x, z, y` + `Uint8Array cls`(한 지역 한 묶음, 선은 오프셋 범위). `N.grid`는 CSR(`Int32Array`). 도로선은 2,048 m 타일 목록으로 질의(`regionRoads(range)`), 전국 경로 찾기는 고속도로·국도 거친 그래프. 부팅 힙 ≤ 900 MB(EV-01과 합쳐 ≤ 500 MB), `window.gc()` ≤ 150 ms.
- 어디·어떻게: 1단계(동작 무변경): `pts[i][0]`을 쓰는 곳을 접근자(`N.px(r, i)` 또는 `r.x[i]`)로 바꾼다 — `carriage.js`, `highways.js`, `hwtraffic.js`, `worldnav.js`, `streetscape.js`, `transit.js`, `game.js`(roadSpot·policeRoadSpot), `citizens.js`, `settlements.js`, `bridgeparts.js`, `views.js`. 2단계: 저장 형식을 SoA로(굽기 `emit.mjs`, `bakefmt.js`는 이미 타입 배열을 blob으로 둔다). 3단계: 타일 질의와 LRU.
- 검증: `unit/roadnet`, `unit/worldnav`(21쌍 경로 동일), `unit/highway-drivable`, `e2e/region-drive`, 픽셀 동일(`cull-identity` 방식으로 고속도로 장면 전후 비교).
- 의존: EV-01과 병렬 가능(다른 파일). 흡수: ADR-0044 "도로 스트리밍".

#### EV-03 할당·GC 다이어트 — P1 · M · Phase 0
- 목적: 메이저 GC 정지 ≤ 8 ms.
- 현재: 700 KB/프레임 할당, 승격 89 KB/프레임(2026-10-09), 1:1 이후 재측정 없음. 믹서 숫자 박싱·WeakMap 처리가 주원인.
- 목표(AC): 걷기·주행 1,500프레임에서 할당 ≤ 200 KB/프레임, 승격 ≤ 10 KB/프레임, 메이저 GC 최종 정지 ≤ 8 ms.
- 어디·어떻게: Chrome 트레이싱으로 1:1 재측정 → 상위 10개 할당처를 고친다(후보: `human.js animateSkinned` 벡터·쿼터니언 재사용, `hwtraffic` 웨이포인트 객체 풀, `fx.js` 파티클, `streetscape` 타일 생성 중간 배열). WeakMap 사용처 목록화.

## 5. 단계와 순서

### 7.2 위험
- **메모리.** EV-01·02 전에는 어떤 화질 작업도 실기기에서 OOM으로 무효가 될 수 있다. 그래서 Phase 0이 먼저다.
- **three.js 구속.** 조명 수 고정(ADR-0002)은 WebGL2 forward의 한계다. EV-40 결정이 늦어지면 R 트랙 절반이 막힌다.
- **실기기 부재.** GPU 목표는 사용자 측정 없이는 닫을 수 없다. 단계마다 사용자 검수 슬롯을 둔다.
- **자료 라이선스.** OSM(ODbL) 파생 자료는 크레딧과 공유 조건 표기가 필요하다(EV-84). CC-BY 음원·모델은 표기 자동화(EV-60).
- **범위 팽창.** 생활 시뮬(LIFE)은 XL이다. Phase 5에서 1단계만. 멀티플레이는 하지 않는다(EV-79).
- **컴파일 비용.** 31조각 직렬 30시간. EV-09 자동화와 조각 병렬 2개(메모리 한도)로.

### 7.3 하지 말 것
- 기존 상용 게임의 이름·캐릭터·차량 상표·지도 레이아웃을 모사하지 않는다(장르·메커닉은 괜찮다).
- GPL·NC·SA 자산을 들이지 않는다.
- 테스트를 비활성화·건너뛰기·격리해서 녹색을 만들지 않는다. 느리면 나눈다(EV-91).
- 픽셀이 바뀌는 변경을 "최적화"라 부르지 않는다. 시각 변경은 ADR + 사진이다.
- 큰 리팩터링과 기능 변경을 한 PR에 섞지 않는다.
- 수치 없이 "자연스러워졌다"고 보고하지 않는다.
- 구운 데이터·`dist/`·zip을 커밋하지 않는다.

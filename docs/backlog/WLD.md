# WLD — 월드·건물

현재: L2~L3, **개선 여지**. 불규칙 도시·보행자 거리·약 300동 입장·층 스트리밍(생성기, 프레임당 3 ms)·엘리베이터·벽 파괴·정전 구역·
외곽 지형/수역. 약점: 실내 반복감, 랜드마크 공간 부족, `building.js`(78 KB)에 계획·생성·가구·런타임·상호작용이 혼재.

불변 조건: ADR-0004(층 생성은 생성기 단계, 한 단계 8 ms 미만), ADR-0006(층 버퍼는 풀에서, dispose 시 반납).
보호 테스트: `floor-population`, `breach`, `entrance-holes`, `cull-identity`(interior), `pool-integrity`.

### WLD-01 `building.js` 분리 — P1 · L · 병행 · Backlog
- 범위: (a) `plan`(층·방 배치, 순수 데이터 — Node에서 단위 테스트 가능) (b) 지오메트리 생성(벽·슬래브·코어·트림) (c) 가구 배치(로비/상가/방) (d) 런타임(문·엘리베이터·조명 스위치) (e) 스트리밍(Buildings 관리자). 동작 변경 없음.
- AC: 파일당 30 KB 이하, `plan`에 Node 단위 테스트(같은 seed → 같은 계획), gameplay·render 스위트 녹색.

### WLD-02 랜드마크 실내 — P1 · M · M3 · Backlog
- 범위: 손으로 설계한 특별 층 3~5종(예: 클럽, 경찰서, 병원 병동, 옥상 바, 갱단 아지트)을 데이터 템플릿으로. GPL-01 루프와 연결되는 장소 우선.
- AC: 각 장소가 지도·휴대폰에 표시되고, 템플릿 데이터만으로 배치된다.
- 의존: GPL-01, WLD-01(c)

### WLD-03 실내 다양성 — P2 · M · Backlog
- 범위: 건물 종류·소득 수준별 팔레트·가구 세트·방 배치 규칙 변주(같은 seed 결정성 유지).
- AC: 무작위 20개 층 스크린샷의 "같은 방 배치" 비율 감소(측정 방법을 티켓 착수 시 정의).

### WLD-04 창밖 실내 표현 — P2 · S · Backlog
- 범위: 아직 지어지지 않은 층의 창에 인테리어 매핑(패럴랙스 큐브맵) 셰이더. 플레이 중 컴파일 0 유지(프리워밍 포함).

### WLD-05 코어 벽 탐침 실패 조사 — P2 · S · Backlog
- 배경: `breach` 테스트(2026-10-09)에서 최고층 탑 첫 타워층의 코어 남쪽 탐침 지점(`core.x0+3, core.z0+6.5`, 남향)에서 `wallAhead`가 벽을 찾지 못했다(코어 동쪽은 정상). 탐침 위치가 코어 배치와 맞지 않는 것인지, 그 면이 파괴 대상에서 빠진 결함인지 미확인.
- 범위: 코어 네 면 각각에서 `wallAhead`가 벽을 찾는지 확인하는 테스트로 확장, 결함이면 수정.
- AC: 코어 4면 모두 파괴 가능하거나, 불가한 면의 이유가 문서화(예: 엘리베이터 문 면).

## 건물 형태 변주 (계획: `docs/design/building-shapes.md`)
불변 조건: 모양은 건물 seed 파생 난수열로만(기존 배치 불변), 단일 단계 건물은 픽셀·동작 동일, 단계 사각형은 포함 관계·최소 변 13 m·코어 사각형이 모든 단계 안에, 플레이 중 셰이더 컴파일 0, 첫 화면 삼각형 +10% 이내.

### WLD-06 단계 데이터 모델 이행 — P1 · M · Backlog
- 범위: `lot.tiers`(받침·탑·왕관 고정)를 `lot.stages[]`(종류·사각형·높이·외관 인스턴스·입장 여부)로 일반화하고 `building.js`(plan·updateSolid·지붕 소품·코어), `world.js`(외관 인스턴스), `relief.js`, `blaze.js`, `garage.js`를 이행. **변주는 켜지 않는다.**
- AC: 전 스위트 녹색, `cull/pack/light-skip` 픽셀 동일, 모든 건물에서 이전과 같은 층 목록·충돌체·인스턴스(스냅샷 비교 테스트), 호환 getter 제거 가능한 상태.
- 의존: 없음

### WLD-12 형태 검증 도구와 구조 테스트 — P1 · S · Backlog (WLD-06과 함께)
- 범위: 건물 전체 형태 컨택트 시트(상공·거리·야간), `e2e/building-shapes.test.cjs`(포함 관계·최소 변·코어·결정론·분포·이웃 간섭), 형태 분포 리포트.
- AC: 테스트가 현재(변주 없음) 상태에서 통과하고 이후 티켓의 합격 기준으로 쓰인다.

### WLD-07 다단 후퇴와 테라스 — P1 · M · Backlog
- 범위: 60 m 이상 건물에 1~3단 후퇴(구역·용도 규칙, 코어 반대편 `x1/z1`로만 줄임), 단계 경계의 테라스 난간·지붕 마감, 후퇴 건물의 내부(층 생성·엘리베이터·벽 파괴·화재·붕괴)가 동작.
- AC: `building-shapes` 분포(60 m 이상의 40% 이상 후퇴), `floor-population`·`breach`·`building-fire`가 후퇴 건물로도 통과, 첫 화면 삼각형 +5% 이내.
- 의존: WLD-06, WLD-12

### WLD-08 왕관·옥상 변주 — P1 · M · Backlog
- 범위: 계단식·피라미드·유리 상자 왕관, 물탱크·헬기장·첨탑·광고 구조물, 구역별 확률. 헬기 착륙장(`garage.js`)과 호환.
- AC: 60 m 이상 건물의 윤곽 종류 5종 이상, 윤곽 분포 리포트, 붕괴 시 왕관이 함께 무너짐.
- 의존: WLD-06

### WLD-09 받침·별관 변주 — P2 · M · Backlog
- 범위: 아케이드·캐노피·2단 받침, 쌍둥이 탑(비입장 별관 포함). 입구·간판·이웃 필지와 겹치지 않는 규칙.
- AC: `entrance-holes`·입구 접근 테스트 통과, 별관이 있는 건물의 화재·붕괴 테스트, 별관이 본관 층 생성 시간을 늘리지 않음.
- 의존: WLD-06, WLD-07

### WLD-10 외벽 문법별 장식 — P2 · M · Backlog
- 범위: 스타일(4종)·용도마다 다른 relief 규칙(수직 핀, 가로 띠, 발코니, 아케이드), RND-07의 외벽 항목과 병합. 삼각형·드로우콜 예산 기록.
- AC: 스타일별 컨택트 시트에서 시각적으로 구분됨, 첫 화면 삼각형 +5% 이내.
- 의존: WLD-06(권장), PERF-02(예산 확정 시)

### WLD-11 비직사각형 평면 조사 — P2 · S · Backlog
- 범위: 모서리 깎기·ㄱ자·원통을 "층 평면 = 직사각형의 합집합"으로 표현할 수 있는지 조사하고 내부(방·벽·AI·내비·벽 파괴·붕괴) 변경 비용 산정. 결과를 ADR로.
- AC: 도입 여부와 범위(예: ㄱ자만)를 문서로 결정, 사용자 승인.
- 의존: WLD-07

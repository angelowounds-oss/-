# GPL — 게임플레이·콘텐츠

현재: L1~L2, **취약 — 제품 관점 최대 리스크**. 시스템은 매우 많지만(무기·부착물·상점·집·일자리·휴대폰·수배·이동 장비·샌드박스)
미션은 짧은 의뢰 7개 내외이고 목표·보상·성장이 이어지지 않는다. 10월 7일 커밋 일부는 "WIP, tests pending" 상태로 남아 있다.

### GPL-01 핵심 루프 정의 (디자인 문서) — P0 · S · M2 · Backlog
- 목적: "플레이어가 왜 계속 하는가"를 한 문서로 정한다. 이후 모든 콘텐츠 티켓의 기준.
- 범위: `docs/design/core-loop.md` — 플레이어 목표(단기 10분 / 중기 1시간 / 장기), 보상(돈·평판·구역·장비), 실패 조건, 기존 시스템 중 루프에 쓰는 것/숨길 것. 후보 2~3안(예: 범죄 경력 사다리, 구역 장악, 도시 생활 시뮬)과 권고안.
- AC: 사용자가 안을 고르고 문서에 "결정"이 기록된다.
- 의존: **사용자 결정**

### GPL-02 데이터 기반 미션 시스템 — P0 · L · M2 · Backlog
- 범위: 미션을 데이터(단계, 트리거, 목표 위치/대상, 보상, 실패 조건)로 정의하는 스키마와 실행기. 기존 미션 7개 이식. 각 미션을 스크립트로 끝까지 진행하는 테스트.
- AC: 새 미션을 코드 수정 없이 데이터 파일만 추가해 만들 수 있다. `e2e/missions.test.cjs`가 모든 미션의 완료·실패 경로를 통과.
- 관련 파일: `src/game.js` (`updateMission`, 미션 정의), `src/jobs.js`
- 의존: GPL-01, ARC-02(테스트 API) — 착수 전 하위 티켓으로 분할.

### GPL-03 WIP 기능 검증 — P1 · M · M0 · Backlog
- 목적: "WIP, tests pending"으로 남은 무기 부착물, 차량 탈출·지붕 타기, 샌드박스의 상태를 확정.
- 범위: 각 기능의 테스트 작성(이전 스크래치 `veh5.js`의 탈출 속도별 피해·지붕 타기·급제동 시 떨어짐 시나리오 포함). 결함은 수정하거나 기능을 숨긴다.
- AC: 세 기능 각각에 테스트가 있고 녹색, 또는 숨김 처리와 사유가 백로그에 기록.

### GPL-04 경제 밸런스 시트 — P1 · M · M2 · Backlog
- 범위: 시간당 수입/지출(일자리, 미션, 판매, 강도, 벌금, 치료, 구매)을 표로 산출하는 스크립트와 조정. 수치는 데이터 파일로 분리(AI-02와 같은 방식).
- AC: 표준 플레이 1시간 시뮬레이션에서 목표 구매(예: 집)까지의 시간이 GPL-01 문서의 목표 범위 안.

### GPL-05 진행 구조 구현 — P2 · L · M3 · Backlog
- 범위: GPL-01에서 고른 장기 진행(평판·구역·경력)을 구현. 착수 시 분할.

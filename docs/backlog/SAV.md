### SAV-01 저장 스키마 버전과 마이그레이션 — P0 · S · M0 · Review (2026-11-08)
- 범위: `snapshot()`에 `v: <정수>` 추가. `load()`에서 `migrate(data)`가 v0(현재 형식)→v1… 순서로 변환. 지금 산발적인 호환 코드(`gear1` 등 "older saves" 처리)를 마이그레이션 함수로 모은다.
- AC: v 없는 기존 저장을 불러오면 v1로 변환되어 게임이 시작된다. 알 수 없는 미래 버전은 덮어쓰지 않고 경고.
- 검증: `tests/fixtures/saves/v0-*.json`(현재 형식 샘플 2~3개) + 새 테스트 `e2e/save-migrate.test.cjs`(로드 → 상태 확인 → 다시 저장 → v 확인).
- 관련 파일: `src/game.js` (`SAVE_KEY`, `load`, `save`, `snapshot`), 상태를 쓰는 모듈들(`memory.js`, `citizens.js`, `items.js`, `power.js`)
- 결과(2026-11-08):
  - `src/savefile.js`: `SAVE_V = 1`. `migrate()`는 버전마다 한 단계씩 올린다(v0→v1: 빠진 `world` 하위 객체를 만들고 돈·미션·은행을 숫자로 정리).
  - 더 새 빌드의 저장(`v > SAVE_V`)은 읽기만 한다. `save()`가 그 위에 쓰지 않고, 부팅 뒤 한 번 알린다.
  - 읽기 순서: 슬롯 → 슬롯 백업(`_bak`, 슬롯이 깨졌을 때, 부팅 뒤 알림) → 슬롯 이전 키(`korea11_v1`) → 새 게임.
  - 모듈별 옛 필드 처리(`items.js`의 `gear1` 등)는 각 모듈에 그대로 둔다. 상태를 만드는 모듈이 그 필드를 가장 잘 알기 때문이다.
  - 픽스처: 단위 테스트 안에 v0 저장 2개(월드 있음/없음)를 둔다(`tests/fixtures` 파일 대신).
- 검증: `node tests/unit/savefile.test.mjs`(v0 변환, 미래 버전, 잘못된 입력, 읽기 대체 순서), `node tests/e2e/save-migrate.test.cjs`(실제 게임에서 v0 슬롯 → 돈 4321·미션 2·은행 77로 시작, 저장 후 v 1, 백업은 v0 원문).

### SAV-02 저장 실패 표시와 용량 예산 — P0 · S · M0 · Review (2026-11-08)
- 범위: `save()` 실패(QuotaExceeded 등)를 토스트로 알리고 재시도. 저장 크기를 측정해 예산(예: 1 MB) 초과 시 오래된 탄흔·이벤트부터 정리. 설정 화면에 슬롯별 크기 표시.
- AC: 용량을 인위적으로 채운 상태에서 저장 실패가 화면에 보인다. 2시간 플레이 상당의 상태에서 저장 크기가 예산 이하.
- 결과(2026-11-08):
  - 실패는 `writeSave()`가 `{ ok, bytes, trimmed, error }`로 돌려준다(`quota`, `over-budget`, 메시지). 게임은 '저장 실패' 토스트(1분에 한 번)와 오류 기록(`errors`, 단계 '저장')을 남긴다.
  - 예산 1 MiB(localStorage 약 5 MB를 슬롯 3개와 백업, 설정이 나눠 쓴다). 넘으면 쌓이는 배열(탄흔, 이벤트, 떨어진 물건, 그을음, 추모비)의 오래된 절반씩을 **저장 사본에서만** 뺀다. 게임 상태는 그대로다.
  - 측정: 탄흔 4만 개와 이벤트 6천 개의 상태가 1,784,956 B에서 911,670 B가 됐다(23,000개 제외, 최신 것은 남음).
  - 휴대폰 설정의 슬롯 줄에 크기(KB)를 표시한다. 깨진 슬롯은 '손상됨 (불러오면 백업 사용)'으로 표시한다.
  - 함께 고침: '초기화'가 슬롯 백업도 지운다(남아 있으면 다음 실행에 옛 게임이 돌아왔다). 다른 슬롯을 불러올 때 다시 열리기 전의 자동 저장을 막는다.
- 검증: 단위 테스트(예산, 백업, 쿼터), `e2e/save-migrate`(저장 거부 → 토스트 '저장 실패', 오류 기록, 슬롯 유지).

### SAV-03 저장 내보내기/가져오기 — P2 · M · Review (2026-11-08)
- 범위: 휴대폰 설정에 파일로 내보내기/가져오기(JSON). 가져올 때 SAV-01 마이그레이션 통과.
- 결과(2026-11-08):
  - 휴대폰 › 설정 › 저장 파일 › 내보내기: 현재 게임을 `korea11-slot<N>-<날짜>.json`으로 내려받는다(예산 적용).
  - 가져오기: 파일을 골라 `importText()`로 검사하고 마이그레이션한다. 다른 JSON(`not-a-save`), 깨진 파일(`parse`), 더 새 빌드의 파일(`future`)은 슬롯을 건드리지 않고 이유를 알린다. 통과하면 현재 슬롯에 쓰고(이전 내용은 백업) 다시 시작한다.
- 검증: 단위 테스트(가져오기 5가지), `e2e/save-migrate`(내보낸 파일의 v·돈, 거절 3가지, v0 파일 가져오기 → 슬롯 v 1).

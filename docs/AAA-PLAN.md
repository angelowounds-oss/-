# AAA-PLAN — 품질 상향 계획 (2026-10-27 사용자 승인)

## Context
- 사용자 요청: "퀄리티를 올리기 위한 대책을 강구해. 트리플 A급 게임까지 올릴 계획을 세워. 필요한 에셋은 직접 오픈소스 등을 이용해."
- 사용자 결정(2026-10-27):
  - 배포: 본체 HTML(노트북 화질, 150 MB 이하) + 스트리밍 고화질 팩. ADR-0013을 확장한다.
  - 라이선스: CC0 + CC-BY(표기). GPL·NC·SA는 쓰지 않는다.
  - 사운드: 녹음 샘플과 합성을 섞는다(AUD-00 결정).
  - 순서: 보이는 화질을 먼저, 게임플레이와 서사는 그 뒤.
- 현재 상태(조사 결과):
  - 렌더: three.js 기본 렌더러. 그림자는 단일 PCF(±85 m, 캐스케이드 없음). 반사(SSR)와 TAA가 없고, GTAO는 ULTRA 화질에서만 켜진다. HDRI는 512×256.
  - 에셋: 텍스처 대부분이 절차 생성이거나 256~1024 px JPG/WebP. GPU 압축(KTX2)이 없다. 지형은 정점 색만 쓰고, 나무는 단순 도형과 셰이더 빌보드다.
  - 캐릭터·차량: 캐릭터는 리그 하나를 색만 바꿔 쓴다(SkinnedMesh 개별, 인스턴싱 없음). 차량은 절차 모델이고 실제 모델은 Ferrari(CC-BY) 하나.
  - 사운드: 전부 합성. 리버브와 HRTF가 없다.
  - 라이선스 위험: 물 셰이더가 GPL-2.0 코드 포팅이다. 출처를 확인하지 못한 에셋도 4건 있다(BLD-04).
- 환경 제약: 이 컨테이너에는 GPU가 없다(SwiftShader). 화질은 사용자 스크린샷으로, 성능은 실기기(PERF-01/02)로 판단한다.

## 원칙
- 불변 조건(ARCHITECTURE §3)을 지킨다.
  - 플레이 중 셰이더 컴파일 0(새 셰이더는 로딩 때 예열).
  - 물리 보간.
  - 층 생성 8 ms 미만.
  - 최적화는 픽셀이 같아야 한다. 시각이 달라지는 변경은 사용자 승인 후 ADR에 기록.
- 화질 등급: LOW·MEDIUM은 지금 비용을 넘지 않는다. 새 효과는 HIGH·ULTRA와 고화질 팩에 둔다.
- 티켓 하나 = 브랜치 하나 = PR 하나. 시각이 바뀌는 PR마다 "기준 장면"(아래 Q0-3) 전후 이미지를 대화로 보낸다.
- 에셋은 모두 받아오는 스크립트와 목록(출처, 작가, 라이선스, sha256)으로 들인다. 크레딧은 이 목록에서 자동으로 만든다.

## 단계 (마일스톤 Q0~Q8, 각 항목 = 티켓)

### Q0 에셋 파이프라인과 기준 (먼저, 모든 단계의 바탕)
1. **Q0-1 에셋 목록과 크레딧**
   - `build/assets/manifest.json`에 url, 작가, 라이선스, sha256을 적는다. `build/assets/fetch.mjs`가 받아 검증하고, `docs/ASSETS.md`와 게임 크레딧 화면을 목록에서 만든다.
   - 기존 BLD-04, UX-04를 흡수한다. 출처를 확인하지 못한 4건은 사용자에게 다시 묻거나 교체한다.
2. **Q0-2 압축 팩**
   - 텍스처는 KTX2(Basis ETC1S/UASTC), 메시는 meshopt로 압축한다. 도구는 gltf-transform과 basisu(wasm 또는 바이너리)이며, 컨테이너에 설치되는지 확인하고 ADR을 쓴다.
   - 팩 형식은 `chunkstore.js`·`bakedload.js`(ADR-0013)의 청크 컨테이너를 넓힌다: `assets/*.pak` 고화질 에셋 팩, 필요할 때 불러옴.
   - KTX2Loader와 transcoder wasm을 본체에 내장한다.
3. **Q0-3 기준 장면 하네스**
   - 고정 카메라 12장면(NEON 밤/낮, 지방 도시, 고속도로 고가, 산, 해안, 실내, 군중, 차량 근접, 비)을 만든다. SwiftShader로 촬영하고 대조 시트를 만드는 `tests/tools/golden-views.cjs`.
   - 실기기에서 같은 장면을 찍는 URL 파라미터(`?view=n`)도 만든다. 사용자 스크린샷 비교용이다.
4. **Q0-4 GPL 물 셰이더 교체**: three.js `Water`(MIT)를 바탕으로 새로 쓴다(Q2-4와 합침).
5. **Q0-5 품질 등급 확장**: `engine.js`의 `QUALITY`에 HIGH·ULTRA 효과 스위치를 추가하고, 팩 유무를 감지한다.

### Q1 렌더링 (빛·그림자·반사)
- **Q1-1 캐스케이드 그림자**: three `CSM` 애드온 방식. HIGH 2단·ULTRA 3단, 먼 단계는 몇 프레임마다 갱신. RND-02를 흡수한다.
- **Q1-2 반사**: HIGH 이상에서 화면 공간 반사(SSR) 패스. 도시 블록마다 미리 구운 반사 프로브(큐브맵, 로딩 때 생성), 젖은 노면과 웅덩이.
- **Q1-3 TAA 또는 개선된 AA**: SMAA 대신 TAA 지터에 맞춰 해상도 동적 조정과 연동(ULTRA). 그 밖의 등급은 SMAA 유지.
- **Q1-4 하늘과 대기**: 물리 기반 하늘(three `Sky`), 시간대별 태양 위치, 고도 안개와 빛줄기(볼류메트릭 근사). HDRI는 Poly Haven 2K로 바꾸되 팩에만 넣는다.
- **Q1-5 색과 노출**: 자동 노출, 3D LUT 색보정(낮·밤·비), GTAO를 HIGH까지.
- **Q1-6 도시 조명**: 가로등·간판 빛의 가짜 반사광(라이트 프로브 격자), 차 전조등 투사.

### Q2 지형·식생·물
- **Q2-1 지형 재질**
  - 원천 텍스처는 ambientCG·Poly Haven CC0(풀, 흙, 바위, 모래, 눈, 논밭).
  - 경사·생물군·`groundfn.js` 값으로 섞는 삼면 투영 스플랫이고, 텍스처 배열을 쓴다(LOW는 지금의 정점 색).
- **Q2-2 나무**
  - CC0 나무 모델(Quaternius 자연 팩 등)과 한국 수종(소나무, 참나무, 은행나무, 벚나무)을 들인다.
  - 근거리는 인스턴스 메시, 원거리는 구운 임포스터 아틀라스로 그린다. `forest.js`의 칸 바이트를 그대로 쓴다.
- **Q2-3 풀과 작은 식생**: 근거리 GPU 인스턴스 풀과 바람.
- **Q2-4 물**: 바다는 거스트너 파도, 반사(SSR 또는 평면 반사), 해안 거품과 깊이 색을 넣는다. 강은 흐름 맵을 쓴다.

### Q3 도로와 도시 (R5·C1·C2·C3를 화질 관점으로 묶음)
- **Q3-1 도로 표현 (R5)**
  - 차선 표시 데칼, 정지선, 횡단보도, 연석과 보도, 노면 마모, 맨홀.
  - 신호등과 표지판은 한국 규격(교통안전표지)으로 만든다(절차 모델 + CC0 텍스처).
- **Q3-2 도시 뼈대 (C1)**: 실제 골목을 따라 블록을 나누고 건물을 배치한다.
- **Q3-3 한국 건축 키트**
  - 아파트 단지(동 번호·복도식/계단식), 상가 건물(층별 간판), 단독·다세대, 편의점, 교회, 학교, 시장.
  - 절차 생성기에 CC0 재질 2K(팩)를 쓴다. 기존 파사드 셰이더, `relief.js`, `citylayout.js`의 STYLES를 넓힌다.
- **Q3-4 한글 간판 (C2)**: Noto Sans KR 같은 OFL 글꼴 부분집합을 내장한다. 상호 목록과 밤 네온 발광을 넣는다.
- **Q3-5 거리 시설 밀도**: 버스 정류장, 가로수, 전신주와 전선, 자판기, 오토바이, 에어컨 실외기.
- **Q3-6 도시 생활 (C3)**: 도시 크기에 비례하는 보행자와 차량, 골목 교통.

### Q4 캐릭터
- **Q4-1 다양한 사람**
  - CC0 모듈형 인물(Quaternius 모듈형 남녀, MakeHuman 출력은 CC0)을 들여 지금 리그(UAL 이름)로 맞춘다. `assets.js`의 `adaptCharacter`를 쓴다.
  - 체형, 옷, 머리, 피부를 조합해 수백 가지 외형을 만든다(CHR-01).
- **Q4-2 군중 LOD**: 30 m 밖은 애니메이션을 텍스처로 구운 인스턴스 군중(VAT), 80 m 밖은 임포스터(RND-04, CHR-03).
- **Q4-3 애니메이션 품질**: 이동 블렌드 스페이스, 발 IK, 시선 처리, 표정 블렌드셰이프(가능한 모델만).

### Q5 차량
- **Q5-1 차량 모델**
  - CC0와 CC-BY 실사 모델로 바꾼다: 세단, SUV, 택시, 버스, 트럭, 경찰차, 오토바이. 한국 도로에 흔한 형태 위주이고 상표는 쓰지 않는다.
  - LOD 3단, 전조등과 브레이크등 발광을 넣는다.
- **Q5-2 손상과 주행감**: 정점 변형 손상, 유리 파손, 타이어 연기와 스키드 자국. 서스펜션과 타이어 곡선 조정은 사용자 플레이 평가로 한다.

### Q6 사운드
- **Q6-1 샘플 도입**: Freesound CC0·CC-BY와 OpenGameArt CC0. 총성(실내/실외 꼬리), 발소리(재질별), 차 엔진(회전수 층), 환경음(도시, 산, 바다, 비).
- **Q6-2 공간음**: HRTF `PannerNode`, 구역별 컨볼루션 리버브(OpenAIR CC-BY 응답), 가림 필터. 음악과 UI는 합성을 유지한다.

### Q7 게임플레이와 표현 (화질 뒤)
- 전투 AI 구조(AI-01·02), 의뢰 풀(GPL-02), 카메라와 조작감, HUD 재디자인, 온보딩(UX-01), "Purge Day" 사건 연출(컷신 시스템, 대사 엔진 LIFE-05).

### Q8 성능과 안정 (전 단계와 병행, 각 단계 끝마다)
- 실기기 기준(PERF-01/02), GC 감소(PERF-04), 예외 복구(PERF-03), 저장 버전(SAV-01/02), CI(BLD-01).
- 등급별 예산: MEDIUM 노트북 내장 GPU에서 1080p 60 fps 목표, ULTRA 데스크톱 1440p 60 fps 목표. 드로우콜과 삼각형 상한을 `docs/PERF-BASELINE.md`에 적는다.

## 검증
- PR마다:
  - `node build/build.mjs`, 해당 단위 테스트, 기준 장면 전후 대조 시트(SwiftShader)를 대화로 보낸다.
  - 최적화 변경은 같은 프레임 동일 비교 테스트.
  - 성능은 렌더를 끈 JS 시간, 할당, 드로우콜과 삼각형 수.
  - `quick`/`all`/e2e는 사용자가 실행한다(기존 합의).
- 단계 끝마다 사용자가 실기기에서 같은 기준 장면을 찍어 fps와 함께 알려 주면, 등급 예산을 맞춘다.
- 에셋은 `fetch.mjs`가 sha256과 라이선스(CC0/CC-BY만 허용)를 검증해야 빌드된다.

# 남은 작업 전체 명세서 (2026-11-21)

이 문서는 게임을 AAA 목표까지 가져가는 데 남은 일을 전부 적은 것이다. 다른 사람이나 다른 AI가 이 문서 하나로 다음 일을 고를 수 있게 썼다.

- 지금 바로 할 일, 빌드 방법, 공통 규칙: `docs/HANDOFF.md`(이 문서의 0단계).
- 티켓의 배경과 실측 기록: `docs/backlog/EV.md`(AAA 작업), `docs/backlog/<파트>.md`(그 전 작업).
- 완료 기준(AC) 원문: `docs/AAA-DIRECTIVE-2026-11-12.md` §4. 이 문서의 "완료 기준"은 그 요약이다.

## 읽는 법

- 상태:
  - Done: 완료 기준 충족.
  - Review: 구현·측정은 했지만 완료 기준 일부 미달. 다음 단계로 넘김.
  - In progress: 진행 중.
  - Todo: 시작 안 함.
  - Blocked: 사용자 결정이나 실기기가 필요함.
- 크기: S 세션 1회 미만 · M 1회 · L 여러 회(시작 전에 하위 티켓으로 나눈다) · XL 단계 전체.
- 우선순위: P0 다음 단계로 넘어가는 조건 · P1 같은 단계의 중요 작업 · P2 여유.
- 숫자는 모두 클라우드 컨테이너에서 잰 값이다(소프트웨어 GPU, 메모리 15 GB). GPU 시간은 재지 않았다. GPU 목표는 사용자 실기기 측정으로만 닫는다.

## 2. 사용자 고정 지시

지침서와 부딪히면 이것이 우선이다.

1. 렌더러는 WebGL2를 유지한다(2026-11-14 결정, ADR-0045 채택). WebGPU로 옮기지 않는다. 클러스터드 조명과 TAA는 직접 만든다.
2. 물리 엔진이 최우선이다. 현실성과 게임성을 파고든다. 메모리가 크게 늘어나는 것은 괜찮다.
   - 메모리 목표(부팅 힙 900 MB, 500 MB)는 목적이 아니라 수단이다. 끊김(GC 멈춤), 부팅 시간, 실기기에서 탭이 죽는 문제를 없애려는 것이다.
   - 현실성과 메모리가 부딪히면 현실성을 고른다. 끊김은 할당 줄이기나 타입 배열 같은 다른 방법으로 잡는다.
3. 월드·zip 용량 상한은 없다. 크기를 줄이려 하지 말고 `docs/PERF-BASELINE.md`에 기록만 한다(CLAUDE.md, 2026-10-31 결정).
4. 사용자가 가진 원본 게임 파일은 고치지 않는다. 실행이나 실험이 필요하면 복사본으로 한다.
5. 작업 중간에 승인을 받지 않는다(사용자가 모두 허용했다).
   - 시각이 바뀌는 변경은 진행하되, 전후 사진과 ADR을 남겨 결과 보고에서 보인다.
   - 8절의 결정은 권고안으로 진행하고, 보고에 "권고안으로 진행함"이라고 적는다.
6. 평가는 빈말 칭찬 없이 냉정하게 한다. 수치 없이 "좋아졌다"고 쓰지 않는다.
7. 사용자에게는 한국어로 보고한다. 코드 주석은 영어로, 이유 중심으로 쓴다.
8. 보안 작업은 방어 관점에서만 한다.

## 3. 저장소 상태 (시작 전에 알 것)

- **게임 코드는 `main`에 없다.**
  - `origin/main`은 다른 프로젝트(계산기 사이트)다.
  - 게임은 기능 브랜치 사슬 위에 있다: … → `feat/WLD-24a-procedural-buildings`(7d74416) → `feat/EV-03-frame-alloc`(지금 작업 브랜치이자 사슬의 끝).
  - 그래서 "티켓 하나 = 브랜치 하나 = PR 하나" 규칙에서 PR을 보낼 대상이 없다(결정 D-1).
- **`origin/wip/EV-41-cascaded-shadows`**(dc2d4e5, 2026-11-15): 캐스케이드 그림자 진행분이다. 7d74416에서 갈라졌고 지금 브랜치에 합치지 않았다. 남은 일은 5절 Phase 2의 EV-41 줄.
- `build/baked`(구운 데이터)는 저장소에 없다. 첫 빌드는 굽기부터 돌고 수도권만도 1시간이 넘는다.
- 빌드 명령, 측정 환경, 공통 규칙은 `HANDOFF.md`에 있다.

- 같은 파일을 두 트랙이 동시에 크게 고치지 않는다. 충돌 위험 파일:
  - `vehicle.js`: 물리 트랙과 EV-24.
  - `hwtraffic.js`: EV-02와 EV-21~23.
  - `game.js`: EV-95와 거의 모든 티켓. 그래서 EV-95 1차를 먼저 끝낸다.
- 굽기 형식이 바뀌는 티켓(EV-02·21·25·37·72, WLD-36)은 형식 버전을 올리고 한 번에 재굽기한다.
- 테스트를 돌리는 동안 빌드를 돌리지 않는다. 메모리 경쟁으로 브라우저가 죽는다(TF-1).
- 큰 리팩터링 커밋과 기능 커밋을 섞지 않는다.

### 남은 양 어림

티켓 크기를 S 0.5, M 1, L 2~3세션으로 놓고 더했다. 지침서의 처음 어림(전체 85~105세션)보다 크다. 지침서 어림에는 마무리 작업과 기존 백로그가 빠져 있었다.

| 묶음 | 세션 |
|---|---|
| Todo EV 티켓 54개(EV-30 제외) + EV-40b | 약 74 |
| EV-30 남은 조각 29개(전체 31개 중 경기·제주 제외) | 약 10 |
| Review·In progress 티켓 마무리 20개 | 약 20 |
| 0단계(TF·BD) | 약 5 |
| 기존 백로그(6절) | 약 10 |
| 합계 | 약 120 |

트랙 2~3개를 동시에 돌리면 벽시계 시간은 그 1/3~1/2이다(지침서 기준).

## 10. 위험과 하지 말 것

### 위험

- **불변 조건이 이미 깨져 있다(TF-8).** 셰이더를 늘리는 작업(EV-41, EV-40b, EV-47)은 이것을 고친 뒤에 해야 판정할 수 있다.
- **실기기 측정이 없다.** GPU 목표(60 fps, 그림자 2.5 ms)는 사용자 측정 없이는 닫을 수 없다. 단계마다 사용자 측정 시점을 둔다.
- **전국 빌드는 외부 서버에 기댄다.** Overpass가 실패하면 빌드가 멈춘다(BD-3).
- **컴파일 비용.** 경기 한 조각이 61분·10.4 GB다. 31조각을 직렬로 돌리면 약 30시간이다. EV-09의 메모리 한도 병렬로 줄인다.
- **자료 라이선스.** OSM(ODbL) 파생 자료와 CC-BY 에셋은 표기가 필요하다(EV-84 크레딧 화면이 자동으로 모은다).
- **범위 팽창.** 생활 시뮬(LIFE)은 XL이다. Phase 5에서는 1단계만 한다.

### 하지 말 것

- 기존 상용 게임의 이름·캐릭터·차량 상표·지도 배치를 따라 하지 않는다(장르와 메커닉은 괜찮다).
- GPL·NC·SA 라이선스 에셋을 들이지 않는다.
- 테스트를 끄거나 건너뛰거나 격리해서 녹색을 만들지 않는다. 느리면 나눈다(EV-91).
- 픽셀이 바뀌는 변경을 "최적화"라고 부르지 않는다. 시각 변경은 ADR과 사진으로 남긴다.
- 수치 없이 "자연스러워졌다"고 보고하지 않는다.
- 구운 데이터(`build/baked`), `dist/`, zip을 커밋하지 않는다.
- 월드·zip 크기를 줄이는 것을 목표로 삼지 않는다(기록만).

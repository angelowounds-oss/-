# ADR-0002 조명 수 고정, 플레이 중 셰이더 컴파일 0
- 상태: 채택(2026-10-09)
- 배경: three.js는 조명 개수·종류를 셰이더 프로그램 키에 넣는다. 조명을 켜고 끄거나 새 재질이 처음 보이면 그 자리에서 프로그램을 컴파일해 50~500 ms 멈췄다(측정 당시 플레이 중 9회).
- 결정: (1) 점/스포트 조명은 로딩 때 품질 단계의 개수만큼 만들고 이후에는 **강도만** 바꾼다(손전등·전조등 포함). (2) 자동 품질 하향은 조명 상한을 유지한다(`setQuality(i, {keepLights:true})`). (3) 로딩 중 `prewarmShaders`가 모든 차량·비행체·군 모델·층 종류를 임시로 배치해 컴파일하고 텍스처를 업로드한다. (4) 꺼진 조명의 BRDF 계산은 `directLight.visible`로 건너뛴다(비트 동일).
- 결과: (+) 플레이 중 컴파일 0(`no-runtime-compile`). (−) 꺼진 조명도 셰이더 루프에 남는다(4번으로 비용 대부분 회수). 메뉴에서 품질을 직접 바꾸면 재컴파일(의도된 예외).
- 재검토 조건: 동적 조명 수가 크게 늘어야 하는 기능(클러스터드 라이팅 등)을 도입할 때.

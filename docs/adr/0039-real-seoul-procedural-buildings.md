# ADR-0039 실제 서울: 도로망 위 절차 건물

## 상태
채택 (2026-10-31, WLD-24a). 사용자 결정: 외부 오픈소스·모델·데이터를 들이지 않고, 저장소에 이미 있는 자료로 서울·인천을 실제 축척으로 만든다. 용량 상한은 두지 않는다.

## 배경
- 건물 윤곽·높이 데이터가 저장소에 없고 새로 받지 않기로 했다. 있는 것은 실제 도로망(OSM 캐시, 컴파일된 `region.bin`의 모든 도로·골목), 물, DEM, 지명뿐이다.
- 정직하게 적어 두는 한계: 도로·강·교량·지형·랜드마크의 위치와 크기는 실제와 같고, 일반 건물 하나하나의 모양과 높이는 실제와 다르다.

## 결정
1. 건물은 컴파일 뒤 한 번 전역으로 만든다(`node build/world/blocks.mjs` → `build/baked/world/capital/buildings.bin`, 커밋하지 않는다). 굽기는 이것을 512 m 타일 청크(`bld/<ti>_<tj>`)로 자른다. 전역으로 한 번 만들므로 타일 경계에서 배치가 어긋나지 않는다.
2. 방법(결정적, 공유 난수열 없음, 위치·도로 id 해시):
   - 4 m 점유 래스터(도로 반폭 + 보도 + 래스터 여유, 물, 가파른 땅 > 0.35, 네온 보존 구역, 공항 도시) → 도로 등급 높은 순으로 양쪽 도로변 필지 → 큰 빈 땅에 아파트 단지(남향 판상 줄·타워) → 깊은 블록의 안쪽 줄(infill).
   - 시가지 여부는 128 m 칸 도로 길이를 7×7로 평균한 값(산·농지는 비운다).
   - 높이·용도는 실제 지구 표(`src/districts.js`: 광화문, 강남, 여의도, 잠실, 송도, 판교, 구월 등의 실제 중심과 반경, 층수 범위, 공항·공원은 비움).
3. 건물 한 채는 회전한 직사각형(중심, 폭, 깊이, 회전) + 층수 + 종류(주택·빌라·상가·업무·아파트·산업·타워) + 모서리 따내기(L자). 타일 상대 0.1 m 정수로 저장한다.
4. uid는 `KR-<ti>_<tj>-<n>`(타일 번호 = floor(x / 512) + 256, n은 타일 안 순번). 80만 채가 넘어 `registry.csv`에 줄을 넣지 않고 타일별 채 수(`buildings-stats.json`)와 이 규칙으로 관리한다. 같은 입력이면 같은 번호이고(두 번 만들어 같은 바이트, 단위 테스트), 도로나 지구 표를 바꾸면 그 타일만 바뀐다.
5. 네온 보존 구역(시청 ±2.1 km)에는 24c까지 세우지 않는다. 24c에서 `KEEP=0`이 되면 같은 컴파일로 채워진다.

## 결과 (2026-10-31)
- 수도권(80 × 62 km) 약 83만 채, `buildings.bin` 7.6 MB, 생성 약 40 s. 단위 테스트 `procedural-buildings`: 도로·물 위 0, 겹침 0, 같은 입력 같은 결과, 남산·백운대 정상 80 m 안 0, 강남 중심의 평균 층수가 가장자리보다 높다.
- 알려진 한계: 시가지 안의 평지 공원은 아파트가 설 수 있다(토지 이용 자료가 없다). 철도는 자료가 없어 비우지 못한다. 건물 모양은 직사각형·L자뿐이다. 랜드마크(롯데월드타워 등)는 24d에서 실제 치수로 절차 생성한다.

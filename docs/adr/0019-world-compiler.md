# ADR-0019 이중 축척, 높이 축척 V, 오프라인 월드 컴파일러

상태: 채택 (2026-10-19, 전체 검토 보고 승인). ADR-0016(축척 1:6.5)을 보완하고, ADR-0018(런타임 도로 지형 맞춤)을 대체할 방향을 정한다.

## 배경 (측정, 2026-10-19)
- 가로는 1:6.5인데 DEM 높이는 실제 미터 그대로다(`worldmap.rawHeight`). 그래서 모든 경사가 6.5배다. 육지 4,000 지점을 쟀더니 경사 중간값이 0.27이고, 46%가 0.30(도로 계획 한도)을 넘었다. 노이즈를 빼도 같다.
- 지형 원자료는 257×257 격자(실거리 2.5 km 간격)이고, 그 사이를 fBm 노이즈로 채운다. 실제 골짜기가 없어서 실제 강·도로가 비탈 위에 놓인다.
- 1:6.5에서 1:1 폭 도로가 땅을 덮는 비율(광주 시청 반경 2 km)은 간선(trunk·primary·secondary)만 넣으면 26%, tertiary까지 45%, 주거 도로까지 72%, 전부 넣으면 97%다. 실제 도로 간격 112 m가 17 m가 된다.
- 실제 고속도로 길이의 11%가 반경 700 m 미만이다. 1:6.5에서 108 m가 되어 0.4 g 기준 시속 74 km가 한계다.
- 지면은 런타임 함수 6개 층(격자, 노이즈, 수도 언덕, 강, 도로·패드, 타일)의 합성이라, 층 사이에 예외가 계속 생겼다.

## 결정
1. **이중 축척.** 지리(위치·해안선·산의 덩어리·강과 도로의 연결)는 1:6.5. 손에 닿는 것(차로 폭·곡선 반경·경사·건물·도로 간격)은 1:1 설계 규칙. 원자료는 반드시 이 규칙에 맞게 일반화한 뒤 쓴다.
2. **높이 축척 V.** 게임 높이 = 실제 높이 × V. 기본 후보는 1/3, 비교 후보는 1/4. 고해상도 DEM으로 다시 재서 사용자가 정한다(M1 산출물).
3. **오프라인 월드 컴파일러(`build/world/`).** 빌드 때 정해진 순서의 래스터 패스로 최종 데이터를 만든다. 순서: 해안 → DEM × V → 물 → 도로(등급 우선순위로 한 번에) → 정착지 부지 → 지표 분류 → 출력(ADR-0013 컨테이너, 기존 t16/t8 형식). 게임은 타일만 읽고, 런타임 지형 함수에는 미세 노이즈만 남긴다.
4. **도로 위계(1:6.5).** motorway·trunk·primary와 농촌 secondary는 실제 선형을 일반화해서 쓴다(상하행 합침, 최소 곡선 반경, 인터체인지 템플릿, 종단 경사 한도). 도시 생활 도로는 실제 간선 블록 안에 1:1 간격(60–120 m)으로 생성한다. 산길은 고개를 넘는 지방도만.
5. **정착지.** 가상 마을은 실제 읍·면(`src/koreaplaces.js`, 한국어 이름)으로 바꾼다. 도시는 실제 간선·강·랜드마크를 뼈대로 절차 블록을 채운다. NEON CITY(수도) 콘텐츠는 유지한다.
6. **검증.** 매 단계 위에서 본 비교 이미지(컴파일 결과 vs 실제 지도)와 고정 지점 스크린샷을 사용자에게 보낸다. 수치 기준은 구현 전에 정하고, 낮추려면 먼저 묻는다.

## 대안 (기각)
- 축척 1:3·1:2: 데이터 4.5–10배, 100 km 전제(빠른 이동·항공·지도·교통)를 전부 다시 잡아야 한다. 컴파일러가 축척과 V를 매개변수로 받으므로 나중의 길은 남긴다.
- 런타임 함수 층을 계속 다듬기(ADR-0018 방식): 층 사이 예외가 사라지지 않는다.
- 모든 도로를 실제 그대로: 위 측정대로 1:6.5에서는 도로가 땅을 덮는다.

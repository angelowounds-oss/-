# ADR-0009 플레이어 캐릭터를 새 리그로 교체하되, 뼈 프레임을 Soldier 규약에 맞춰 코드는 그대로 둔다

- 상태: 채택 (2026-10-16, CHR 캐릭터 교체)
- 맥락: 사용자가 "새 GLB(178개 클립)로 전면 교체, 기존 에셋은 폐기하지 말고 보관"을 승인했다(외형 변경 허용, 마네킹형 그대로, 라이선스 확인 완료·표기 의무 없음). 새 파일의 뼈는 `pelvis`/`upperarm_l`… 이름이고 뼈마다 로컬 축이 Soldier와 150~180° 다르다. 무기 장착(`RightHand`), 소총 IK, 앉기·운전 오프셋(`AIM`), 래그돌(`BIND`)은 Soldier 뼈 프레임을 전제로 튜닝돼 있다. 클립을 뼈 이름으로만 옮기면(리타깃 미리보기에서 두 번 실패) 팔다리가 엉뚱한 방향으로 꺾인다.
- 결정:
  - `src/assets.js`의 `adaptCharacter`가 로드 직후 한 번 다음을 한다: ① 뼈 이름을 게임 규약(`Hips`, `Spine1`, `LeftArm`…)으로 바꾼다, ② 매핑된 뼈의 기준 프레임을 Soldier의 월드 기준 프레임(`SOLDIER_REST`, 게임에서 Soldier를 π 돌린 것과 같은 상태)으로 다시 표현한다 — 뼈 위치는 그대로 두고 로컬 회전만 `K_parent⁻¹·q·K_bone`으로 바꾸므로 스킨 바인드 행렬도 `R(K)⁻¹·inverse`로 보정하면 기본 자세와 변형이 그대로다, ③ 클립 트랙도 같은 식으로 바꾼다, ④ 게임이 쓰는 클립만 `CLIPS` 표대로 게임 이름(`U_*`, `Idle/Walk/Run`, `TPose`)으로 가져오고 `UB_Pistol_*`는 `U_Pistol_*`에서 다리·골반·root 트랙을 뺀 상체 클립으로 만든다.
  - 캐릭터 파일은 +Z를 보므로 게임에서 π 회전을 하지 않는다(`CHARACTER_YAW = 0`), 발 중심이 Soldier보다 0.09 m 뒤라 `CHARACTER_SHIFT_Z`로 맞춘다(앉기·운전·웅크리기 오프셋 유지).
  - 번들에는 게임이 쓰는 클립만 담은 `assets/character_game.glb`(33개, 2.7 MB)를 넣는다. `build/prune_character.mjs`가 원본 `assets/Character.glb`(178개, 12.8 MB, 클립이 90%)에서 만든다. 원본과 `assets/Soldier.glb`는 저장소에 보관만 하고 번들에 넣지 않는다.
- 결과: 게임 코드(`human.js`, `ragdoll.js`, 무기·IK)는 바뀌지 않았다. `character` 테스트가 로드·클립 존재·방향(+Z, 왼팔 +X)·엉덩이 높이(서기·앉기·운전·웅크리기)·발이 땅 아래로 가지 않음·스킨 늘어남 없음·권총이 손에 있음·래그돌 유한성을 지킨다. 번들 크기는 거의 같다(31.5 MB).
- 한계: 새 메시는 마네킹형(머리카락·옷 없음)이라 군중 다양성은 CHR-01 그대로 남는다. 삼각형이 모델당 11.4k→13.8k(+21%), 뼈가 49→66개(+35%)지만 클립당 트랙은 156→67이라 애니메이션 계산은 줄 수 있다 — 시민이 많은 장면의 실제 비용은 PERF-01/02(실기기)에서 확인한다. 걷기 속도와 클립 길이가 달라 발 미끄러짐은 CHR-02에서 재야 한다. 클립 이름 매핑(`CLIPS`)에서 일부는 대체물이다(`Run`→`Jog`, `U_Death01`→`Death_A` 등).
- 되돌리기: `src/assets.js`의 import를 `Soldier.glb`로 바꾸고 `adaptCharacter`를 건너뛰면 된다(`CHARACTER_YAW`는 π).

# 생활 시뮬레이션 구현 프롬프트 (LIFE)

결정 근거는 `docs/adr/0014-life-simulation.md`, 티켓은 `docs/backlog/LIFE.md`에 있다.
**사용법**: 새 세션을 열고 §0 공통 지침과 해당 단계의 프롬프트 하나를 그대로 붙여 넣는다. 단계는 순서대로 진행한다.
각 단계 프롬프트에는 앞 단계 결과에 대한 가정이 들어 있다. 앞 단계가 끝나지 않았다면 먼저 그 단계를 끝낸다.

## §0 공통 지침 (모든 단계 프롬프트 앞에 붙인다)

```
너는 /home/user/- 저장소(퍼지데이 / 네온 시티 v9, 단일 HTML three.js r180 + Rapier 오픈월드)에서 작업한다.
브랜치 neon-city-v9. 먼저 CLAUDE.md, docs/ARCHITECTURE.md(§3 불변 조건), docs/adr/0014-life-simulation.md,
docs/prompts/LIFE-SIM.md §1~§3, docs/backlog/LIFE.md를 읽어라.

고정 결정(바꾸지 말 것): 규칙 기반 AI만(외부 LLM·네트워크 금지), 생활 시스템은 퍼지와 분리, 등록 시민 전원이 깊은 관계,
1년 = 게임 28일(미성년 4배속), 연애 대상은 성별 무관한 성인만, 영구 사망, 미성년자 보호(§3.8).

작업 규칙:
- 대화는 한국어, 코드 주석은 영어(이유 중심, 주변 코드 밀도에 맞춤). 기존 코드 대량 재포맷 금지.
- 불변 조건: 플레이 중 셰이더 컴파일 0(새 재질은 prewarm에 포함), 로직은 v.x·화면은 v.rx, 생성기 한 단계 8 ms 미만.
- 성능 주장은 렌더를 끈 JS 시간·할당·드로우콜로만(GPU 없음, SwiftShader).
- 데이터(대사, 규칙표, 수치)는 src/data/ 아래 파일로 분리하고 코드에 매직 넘버를 흩뿌리지 않는다.
- 새 테스트는 tests/e2e/<이름>.test.cjs로 만들고 tests/run.cjs에 등록한다. 테스트를 동시에 두 개 돌리지 않는다.
- 끝나면: 해당 테스트 + node tests/run.cjs quick 통과(렌더·성능·월드를 건드렸으면 all), docs/backlog/LIFE.md 상태 갱신,
  필요하면 ADR-0014·ARCHITECTURE.md·PERF-BASELINE.md 갱신, 커밋 후 git push -u origin neon-city-v9.
- 빌드 산출물(dist/, zip, build/baked/)은 커밋하지 않는다. node build/build.mjs --zip으로 빌드해 zip을 SendUserFile로 전달한다(ADR-0034).
- 사용자가 정해 주지 않은 세부는 §1~§3 설계를 따르고, 거기에도 없으면 가장 좋은 방법을 스스로 정해 진행한 뒤 보고에 적는다.
  디자인·에셋·라이선스처럼 사용자가 정할 일만 선택지와 권고안으로 묻는다.
```

## §2 공통 설계

### 2.1 모듈 (모두 `src/` 바로 아래, 기존 평면 구조에 맞춤)

| `people.js` | 인물 명부: 지역별 원본 생성(순수), LRU 캐시, 변경분, id 체계, 조회 색인 |

→ `events` 순으로 갱신한다(ARCHITECTURE.md §2에 추가).

### 2.2 인물 id와 원본
- id 문자열: 수도 `c<n>`, 도시 `t<cityIdx>.<n>`, 마을 `v<villageId>.<k>`(기존 `v.residents[].id` 유지), 농장 `f<id>.<k>`, 태어난 아이 `b<serial>`.
- 원본 생성: `base(id)`는 `mulberry32(hash(id) ^ WORLD_SEED)`만 사용한다. `Math.random` 금지. 같은 id는 언제나 같은 원본이다.
- 원본 필드: `name, female, birth`(사회 달력 날짜), `persona`, `job, workplace, home`(지역별 주소 객체), `household`(id), `region`.
- 도시 명부 크기: `clamp(round(city.r / 7), 240, 600)`. 집은 그 도시 `citylayout`의 주거 블록, 직장은 상업·업무 블록.
- 변경분: `G.state.people = { v: 1, d: { [id]: {필드: 값} }, born: [아이 원본 레코드], seq }`. 조회는 `get(id) = merge(base(id), d[id])`.
- 캐시: 최근 2,000명 LRU. 전체 순회 API(`forRegion(region, fn)`)는 사회 틱에서만 쓴다.

### 2.3 성격과 궁합 (`persona.js`)
- 5축(0..1): 외향, 친화, 성실, 정서 안정, 개방. 특성 2~3개: 다정함, 질투심, 야망, 신앙심, 겁 많음, 술꾼, 수다쟁이, 냉소적, 낭만적,
  가정적, 모험가, 원칙주의, 허세, 내성적 예술가 등 16종(상충 쌍은 같이 뽑지 않음).
- 취향: 좋아하는 음식 2, 장소 2, 선물 종류 2, 대화 주제 3, 싫어하는 것 2(주제·행동).
- 연애 선호: 끌리는 성별 집합(성인 NPC마다, 분포: 이성만 80%, 동성만 8%, 둘 다 12%), 선호 나이 차 범위, 중시하는 것(외모 평판, 재력, 다정함, 위험한 매력).
- 궁합 `compat(a, b)` = 축 거리 + 특성 상성표 + 취향 겹침. -1..1. 플레이어 "성격"은 대화 선택 이력(친절/거침/유머/진지)으로 정한다.

### 2.4 사회 달력 (`calendar.js`)
- `Clock.t`(분)에서: 하루 1,440분, 1주 7일(월~일, 토·일 휴일), 계절 7일 × 4 = 1년 28일. 게임 시작일 = 1년 봄 월요일.
- 나이: 성인은 `(today - birth) / 28`. 0~17세 구간은 4배속(ADR-0014 §8). `ageOf(person, today)`가 유일한 계산 지점이다.
- 생일 = `birth % 28`. 휴일: 계절마다 1일(봄 축제, 여름 해변, 가을 수확, 겨울 등불).
- 시작 시점의 나이 분포는 기존 `citizens.js` 분포를 유지하도록 `birth`를 거꾸로 계산한다.

### 2.5 관계 그래프 (`bonds.js`)
- 간선 키: `a < b` 정렬한 `a|b`. 값: `{ aff: -100..100(호감), trust: 0..100, attr: 0..100(끌림), fam: 0..100(친숙도), grudge: 0..100,
  kind: 'family'|'household'|'coworker'|'neighbor'|'friend'|'romance'|'rival'|null, stage(연애), rel(가족: parent|child|sibling|spouse|ex),
  last: 마지막 접촉일, hist: [최근 사건 코드 4개] }`.
- 초기 간선(순수): 같은 가구(가족·동거인), 같은 직장 단위(동료, 최대 8), 같은 층·같은 집(이웃, 최대 6), 원본 시드로 뽑은 오랜 친구 0~3(같은 지역), 기존 커플·부부.
- 저장: 원본과 다른 간선 + 플레이어(`P`)와의 모든 간선만. `G.state.bonds = { v:1, e: { key: 값 } }`.
- 감쇠: 읽을 때 `days = today - last`로 친숙도·호감을 `src/data/social.js` 비율만큼 줄인다(가족은 하한 유지).
- 단계 전이는 함수 하나(`advance(edge, event)`)에 표로 모은다.

### 2.6 인물 기억 (`pmemory.js`)
- 인물마다 고리 버퍼 12칸: `{ day, code, who, place, val(-3..3), imp(1..5) }`. 중요도와 경과일로 잊는다(imp 5는 잊지 않음).
- 사건 코드: 도움받음, 선물, 칭찬, 모욕, 협박, 폭행당함, 가족 피해, 데이트(좋음/나쁨), 약속 어김, 결혼식 참석, 장례식 등.
- `memory.js`의 목격·소문을 연결한다. 목격한 범죄는 목격자의 기억이 되고, 소문은 관계 그래프를 따라 하루 틱에서 퍼진다(친숙도가 높을수록 잘 퍼짐).
- 의견: `opinion(npc, P)` = 간선 호감 + Σ(기억 val × imp × 망각) + 평판(갱단 구역, 수배). 대화·장면·사회 틱이 같은 함수를 쓴다.

### 2.7 일정 (`schedule.js`)
- `plan(person, day)` = 원본 일정(직업, 요일, 나이, 성격: 외향이면 저녁 외출 많음) ⊕ `overrides(person, day)`.
- 덮어쓰기 구간: `{ t0, t1, kind: 'date'|'visit'|'event'|'errand'|'move'|'home', place, with: [id] }`. 저장 위치 `G.state.people.d[id].ov`(지난 날은 정리).
- `where(person, t)`는 지금처럼 순수 함수로 남긴다. 실체화된 사람만 실제로 걷는다.

### 2.8 대화 (`dialogue.js`)
- 진입: NPC에게 F(대화) → `talk` 패널. 첫 줄은 NPC가 상황에 맞게 먼저 말한다(관계·기분·시간·장소·최근 기억·날씨).
- 선택지(상황에 맞는 3~5개): 잡담(주제: 날씨, 일, 동네 소식, 뉴스, 다른 사람 이야기), 칭찬, 농담, 고민 듣기, 선물(가방에서), 부탁(도움·태워 주기·돈),
  같이 하자(활동 초대), 데이트 신청, 고백, 청혼, 사과, 협박, 모욕, 작별.
- 판정: `p = sigmoid(w1·compat + w2·mood + w3·opinion + w4·contextFit − threshold[intent][stage])`. 결과 성공/보통/실패 → 간선·기억 변화.
  모든 가중치와 임계값은 `src/data/social.js`에 둔다.
- 대사: `src/data/lines/<intent>.js`에 감정(기쁨, 보통, 불쾌, 분노, 수줍음) × 말투(존댓말 해요체, 반말, 격식 합쇼체) 템플릿.
  `{name}`, `{place}`, `{food}` 같은 칸과 조사 도우미 `josa(word, '은/는')`(받침 판정). 같은 대화에서 같은 줄을 반복하지 않는다(대화 이력).
- 말투 규칙: 처음 보는 성인 → 해요체, 나이 많은 상대·직장 상사 → 해요체/합쇼체, 친구·연인·가족·아이 → 반말(친숙도 60 이상이고 나이 차 10 미만이면 반말 제안).
- 미성년자에게는 협박·모욕·연애 계열 선택지를 만들지 않는다.

### 2.9 활동 (`activities.js`)
- 식사·술·카페: 가게 안 좌석 두 자리를 마주 보게 잡고 `Sitting_*` 클립을 쓴다. 주문 메뉴(가격, 욕구 회복), 대화 3라운드, 분위기 점수(장소 취향, 시간대, 술 양, 가게 혼잡도).
- 드라이브: NPC가 조수석에 탄다(`Driving` 좌석 자세 재사용). 속도·충돌·경치(바다, 산, 야경)·음악 취향으로 점수가 바뀐다. 목적지는 그 NPC가 좋아하는 장소.
- 산책: 플레이어 옆에서 속도를 맞춰 걷는다(연인이면 손잡기). 주기적으로 말풍선 대사.
- 활동 결과는 간선과 기억에 반영한다. 활동 중 범죄·총격이 일어나면 활동이 끝나고 큰 부정 기억이 남는다.

### 2.10 연애·결혼 (`romance.js`, `household.js`)
- 단계: 낯선 사람 → 아는 사이 → 호감(썸) → 연인 → 약혼 → 결혼(→ 이혼/사별). 각 전이는 조건(끌림, 호감, 신뢰, 데이트 횟수, 기억) + 행동(고백, 청혼).
- 질투: 연인·배우자가 있는데 다른 사람과 데이트하는 것을 본 목격자 소문이 배우자에게 닿으면 큰 부정 기억이 생긴다. 질투심 특성이 배율을 키운다.
- 결혼: 날짜를 잡으면 결혼식 행사(§2.12). 이후 동거: 플레이어 집이 있으면 배우자가 이사 오고, 없으면 플레이어가 배우자 집에 들어간다.
- 가계: 주 1회 정산(집세·생활비, 배우자 수입의 일부가 공동 잔고에), 휴대폰에 가계부. 이혼하면 공동 잔고를 나누고 한쪽이 집을 떠난다.
- 배우자는 자기 직업·일정을 유지하고, 집에서는 요리, TV, 대화, 잠, 집안일을 한다. 기념일·생일을 잊으면 부정 기억이 남는다.

### 2.11 사회 틱과 장면 (`socialsim.js`, `scenes.js`)
- 하루가 바뀌면 지역별 큐에 사람을 넣는다. 프레임당 1 ms 예산 안에서 처리한다(게임 하루 = 실제 24분이므로 충분하다).
- 사람마다 하루 1회: 간선 몇 개를 고르고(친숙도 가중), 만남 확률(일정이 겹치는지) → 사건 표 굴림(친해짐, 다툼, 연애 시작, 이별, 결혼 결정, 이사, 이직, 출산, 노환 사망).
  인구 유지: 지역 인구가 원본보다 10% 이상 줄면 이주자(새 원본 id)를 들인다.
- 결과 중 주목할 만한 것(결혼, 출산, 사망, 큰 다툼)은 뉴스·소문·휴대폰 알림으로 보낸다(아는 사람 관련이면 우선).
- 장면: 실체화된 두 사람이 4 m 안에 있고 간선(친숙도 30 이상 또는 원한 40 이상)이 있으면 확률적으로 장면을 연다. 동시에 최대 6개, 사람당 쿨다운.
  종류: 인사(멈춤, 마주 봄, 손 흔들기), 대화(`Idle_Talking`, 말풍선 3~6줄), 함께 걷기(연인이면 손잡기), 다툼(빠른 손짓, `Push`, 주변 시민이 쳐다봄),
  포옹(절차적 상체 자세), 같이 식사(가게 좌석). 말풍선은 대화 엔진의 같은 문법으로 만든다(NPC끼리 대사).
- 플레이어가 장면에 끼어들 수 있다(F: 인사하기, 말리기).

### 2.12 행사 (`events.js`)
- 행사 = `{ id, type, day, t0, t1, venue, host, guests: [id], state }`. 손님 일정에 덮어쓰기 구간을 넣는다.
- 플레이어가 장소 근처에 있으면 손님을 실체화해 역할 자리(좌석, 둘러선 원)에 둔다. 진행 순서는 행사 종류별 대본(예: 결혼식 입장 → 서약 대사 → 박수 → 축하 대화).
- 생일(케이크 소품, 노래 말풍선), 결혼식(교회·광장), 장례식(`citizens.js` 추모 소품 재사용, 조문 대화), 계절 축제(광장에 노점·사람 모임).
- 초대는 휴대폰 문자로 온다. 가지 않으면 관계에 따라 부정 기억이 남는다.

### 2.13 원한 (`grudges.js`)
- 플레이어가 누군가를 다치게 하거나, 물건을 훔치거나, 가족을 죽이면 피해자와 가족·친한 친구의 간선에 원한이 쌓인다.
- 반응은 성격으로 고른다: 신고(기존 범죄 시스템), 말로 따짐, 소문 퍼뜨리기, 가게 거래 거절, 복수(성인만, 갱단 연고가 있으면 무장), 피하기.
- 화해: 사과(대화), 선물, 보상금, 시간 경과, 그 사람을 도와준 기억.

### 2.14 자녀·가족 (`family.js`)
- 부부(또는 연인 동거)가 원하면 임신(이성 부부) 또는 입양(모든 부부). 임신은 한 계절(7일). 출생 시 새 원본 `b<serial>`이 `G.state.people.born`에 저장된다.
- 성장 단계: 아기(0~2), 어린이(3~12), 청소년(13~17), 성인(18). 단계별 일정(집·어린이집·학교), 대화 선택지(놀아 주기, 숙제 돕기, 칭찬, 꾸중 — 폭력 없음).
- 성인이 되면 일반 시민처럼 직업을 얻고, 집을 떠날 수 있다.
- 아이 모델: 성인 리그의 뼈 비율 조정(키 0.55~0.9배, 머리 비율 크게, 팔다리 짧게). `assets.js`의 리그 매핑(ADR-0009)을 그대로 쓰고, GLB를 받으면 교체한다.

### 2.15 휴대폰·UI
- 휴대폰 탭 "사람": 연락처(만난 사람), 관계 단계·호감 막대, 알게 된 특성(대화로 드러남), 가족 관계도, 전화(대화 엔진 축약판)·문자(약속 잡기).
- 알림: 초대, 생일, 기념일, 소문("○○ 씨가 당신 이야기를 하고 다닌대요"), 가족 위험 알림.
- 이름표: 아는 사람은 이름·관계를 표시하고, 모르는 사람은 "시민"으로 표시한다.

### 2.16 성능·저장 예산 (모든 단계 공통 AC)
| 항목 | 예산 |
|---|---|
| 사회 틱 | 프레임당 ≤ 1 ms(렌더 끈 JS 시간), 게임 하루 안에 전 지역 처리 |
| 장면 | 6개 동시일 때 ≤ 0.4 ms/프레임 |
| 대화 판정·대사 생성 | 1회 ≤ 2 ms |
| 명부 조회 | `get(id)` 캐시 적중 ≤ 2 µs, 원본 생성 ≤ 50 µs |
| 저장 크기 | 게임 10일 집중 플레이 후 `G.state.people + bonds` ≤ 300 KB |
| 셰이더 | 새 프로그램 0(`no-runtime-compile`) |

### 단계 4 — 함께 하는 활동

## §3.8 미성년자 보호 (모든 단계에 적용되는 불변 조건)

# 보완 작업 명세서 (인계용, 2026-11-21)

다른 사람이나 다른 AI가 이어서 작업할 때 읽는 문서다. 작업 규칙은 `CLAUDE.md`, 티켓의 자세한 배경은 `docs/backlog/EV.md`에 있다.

## 시작 상태

- 브랜치: `feat/EV-03-frame-alloc` (EV-03 끝, 아직 main에 합치지 않음).
- `build/baked`(구운 지도 데이터)는 저장소에 없다. 처음 빌드할 때 굽기부터 돌고, 수도권만도 1시간 넘게 걸릴 수 있다.
  - 수도권 빌드: `WORLD_PROVINCES= node build/build.mjs --zip` (지금까지의 전달물은 모두 이 빌드).
  - 기본값(전국)은 외부 지도 서버(Overpass)에 기대다 실패한다(BD-3).
- 의존성: `cd build && npm i && cd ..`.
- 모든 숫자는 클라우드 컨테이너(소프트웨어 GPU, 메모리 15 GB)에서 잰 값이다. GPU 시간은 재지 않는다.

## 개요

가장 먼저 할 일은 메모리 크기(1.7 GB)를 줄이는 것이다. 플레이 중 끊김(0.045~0.135초)의 길이가 쓰는 메모리 양에 비례하기 때문이다.

- 끝난 일(EV-03, 커밋 909beed): 프레임마다 새로 만드는 메모리를 걷기 886~945 → 534 KB, 주행 984~1,106 → 463 KB로 줄였다. 차·사람 객체 구조를 하나로 통일했고(12 → 1, 30 → 1), 무게중심 좌표 버그(`physorigin`이 `worldCom`을 감싸지 않음)를 고쳤다.
- 항목마다 할 일, 완료 기준(측정 테스트와 숫자), 우선순위(P0 가장 급함 ~ P2)를 적었다.

## 작업 순서와 공통 규칙

측정 도구와 전달 문제를 먼저 닫고, 그다음 메모리·부팅, 마지막에 데이터·지역을 한다. 날짜는 정하지 않았다.

1. TF-1 교통 감사 단독 재실행, BD-1 zip 자동 나누기, EV-93 측정 관문 두 개. 이후 작업의 판정 기준이 된다.
2. EV-01 검증·커밋.
3. PF-1 메모리 구성 측정 → 줄이기 → PF-3 GC 멈춤 재측정.
4. PF-2 부팅 시간.
5. PF-4·PF-5 프레임 할당, EV-05 도시 진입 끊김, EV-04.
6. TF-2~TF-7 데이터 테스트와 WLD-36을 한 번의 재굽기로 묶어 처리.
7. BD-3 → EV-09 → WLD-25 전국 확장, BD-2 크기 줄이기.

공통 규칙

- 티켓마다 브랜치 하나, 커밋 전 `node tests/run.cjs quick`.
- 플레이 중 셰이더 컴파일 0회(`no-runtime-compile`), 물리 보간 유지(`physics-interp`).
- 성능 주장은 수정 전·후를 같은 컨테이너에서 잰 숫자로만 하고, GPU 시간은 주장하지 않는다.
- 테스트를 돌릴 때는 빌드를 동시에 돌리지 않는다(TF-1의 교훈).
- `build/baked`, `dist`, zip은 커밋하지 않는다.
- 사용자에게는 한국어로 보고한다. 코드 주석은 영어, 이유 중심.
